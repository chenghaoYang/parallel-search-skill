## 分类轴 v0
- 轴1 协议谱系（请求形状继承自谁）：CC = Chat Completions 系；RS = Responses 系；MS = Messages 系；GC = generateContent 系；X = 其他独立协议（待 scout）
- 轴2 状态位置：无状态（客户端每次回传全量历史） / 服务端可存（id 链或会话对象）
- 轴3 与参照的关系：原生（协议所有者） / 厂商兼容层 / 网关转换 / 自托管推理服务

## 维度 A（核心协议）
- D1 入口：怎么发起一次调用？（base URL、路径、鉴权/版本 header、模型放哪）
- D2 输入：对话怎么表示？（容器、角色枚举、内容块类型、多模态）
- D3 指令：系统提示放哪？
- D4 状态：对话历史谁保存？
- D5 工具：函数怎么定义、调用、回传？（schema 字段、id 关联、tool_choice、并行、strict）
- D6 内置工具：厂商替你执行哪些工具？
- D7 推理：怎么开/控预算？推理内容怎么返回、是否必须回传？
- D8 生成控制：输出长度字段、采样参数、stop、n、结构化输出
- D9 流式：SSE 事件模型与结束信号
- D10 响应/用量：结果在哪、停止原因枚举、usage 字段名
- D11 缓存：自动/显式、怎么标、怎么计
- D12 同厂其他入口：同一厂商还提供哪些他家方言兼容层 / 新协议？

## 维度 B（下游/生态，相对参照协议的差异）
- B1 入口：兼容 base URL、鉴权
- B2 方言覆盖：实现了哪些参照协议、哪些端点
- B3 字段落差：哪些参照字段被忽略/不支持/报错
- B4 推理差异：开关、返回字段、回传要求与参照有何不同
- B5 工具差异：tool_choice / 并行 / strict / 内置工具
- B6 多模态差异：图像/文档在兼容模式是否可用
- B7 缓存与用量差异：缓存机制、usage 字段名
- B8 参数语义差异：温度范围/映射、max_tokens 默认、模型名映射、其他怪癖
