下面是这几家大模型 HTTP API 在**请求协议层面**的核心差异，面向需要做协议适配或写网关层的工程师。每条都附了官方文档链接。

## 1. OpenAI：Chat Completions vs Responses

两个接口都是 `POST`，但路径、输入字段和部分参数名不同：

| 维度 | Chat Completions | Responses |
|---|---|---|
| 路径 | `POST /v1/chat/completions` | `POST /v1/responses` |
| 对话输入字段 | `messages`（数组，role 可为 system/developer/user/assistant/tool） | `input`（可为字符串，或 EasyInputMessage / ResponseOutputMessage 等组成的数组） |
| 系统提示位置 | 放在 `messages` 数组里，role 为 `system` 或 `developer` | 顶层字段 `instructions`，不放 `input` 里 |
| 生成参数 | `max_completion_tokens`、`temperature` 等 | `max_output_tokens`、采样参数命名相同 |
| 状态管理 | 无状态，历史全量回传 | 支持有状态（`previous_response_id` / `store`），历史可留在服务端 |

文档：[Create chat completion](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create/)、[Chat Completions Overview](https://developers.openai.com/api/reference/chat-completions/overview/)、[Create a model response](https://developers.openai.com/api/reference/resources/responses/methods/create/)、[Responses Overview](https://developers.openai.com/api/reference/responses/overview/)。迁移适配时注意：`input` 的直接字符串等价于一条 user 消息，这与 `messages` 的"必须显式给 role"是关键差别。[1][2][3][4]

## 2. Anthropic Messages

- 路径：`POST /v1/messages`（全量 URL `https://api.anthropic.com/v1/messages`）[5]
- 系统提示：顶层字段 `system`（字符串或 TextBlockParam 数组），**不属于** `messages` 数组。官方明确说明"there is no `"system"` role for input messages in the Messages API"[6]
- 输入消息：`messages` 数组，role 只允许 `user` / `assistant` 交替出现；每个消息为 `{role, content}`，content 可为字符串或 content block 数组[6]
- `max_tokens` 是必填参数，这点与 OpenAI 不同（OpenAI 的对应参数可选）
- 例外情况：在部分新模型（文档列出的 Fable 5.1、Opus 5 等）上，允许在 user 轮次之后插入 `role: "system"` 的消息做"对话中途系统指令"，但**不能**是 messages 数组的第一条；首轮全局指令仍走顶层 `system`[7]

文档：[Create a Message](https://platform.claude.com/docs/en/api/messages/create)、[Using the Messages API](https://platform.claude.com/docs/en/build-with-claude/working-with-messages)。[6][7]

## 3. Google Gemini generateContent

- URL：`POST https://generativelanguage.googleapis.com/v1beta/{model=models/*}:generateContent`——模型名直接拼在路径里（如 `models/gemini-3.8-flash:generateContent`），不在请求体的 `model` 字段中；流式走 `:streamGenerateContent`[8][9]
- 对话内容字段：`contents`，数组，元素为 `{role, parts}`，role 取 `user` / `model`（注意是 `model` 不是 `assistant`），文本包在 `parts[].text` 里[9]
- 系统指令字段：`system_instruction`（纯 REST 下为 snake_case；Vertex AI 风格为 camelCase 的 `systemInstruction`），是独立的 Content 对象，不进 `contents`；其 `role` 字段会被忽略[10][11]
- REST 无状态，多轮对话需全量历史回传[9]

文档：[Generating content（REST 参考）](https://ai.google.dev/api/generate-content)、[generateContent 快速上手](https://ai.google.dev/gemini-api/docs/generate-content/get-started)、[Gemini Enterprise 推理参考](https://docs.cloud.google.com/gemini-enterprise-agent-platform/reference/models/inference)。[8][9][10]

## 4. DeepSeek：OpenAI / Anthropic 双兼容

- OpenAI 兼容 base URL：`https://api.deepseek.com`（也可用 `https://api.deepseek.com/v1`，官方注明这里的 `v1` 与模型版本无关）[12][13]
- Anthropic 兼容 base URL：`https://api.deepseek.com/anthropic`，对应环境变量 `ANTHROPIC_BASE_URL`，请求格式即 Anthropic Messages[12][14]
- 思考内容字段：
  - OpenAI 格式下，思维链（CoT）放在消息里的 `reasoning_content`，与 `content` 同级；带 `tools` 的后续请求必须把历史 `reasoning_content` 完整回传，否则返回 400；不带 `tools` 时回传会被忽略[15]
  - Anthropic 格式下，对照 Anthropic 的 `thinking` content block——官方兼容性表中 `content` 数组里 `type="thinking"` 标记为 Supported，`type="redacted_thinking"` 不支持[14]
- 也原生支持 Responses 格式（同一 base URL，`client.responses.create`），当前仅限部分模型（如 deepseek-v4-flash）[16][17]

文档：[Your First API Call](https://api-docs.deepseek.com/)、[Using the Anthropic API](https://api-docs.deepseek.com/guides/anthropic_api/)、[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)、[Using the Responses API](https://api-docs.deepseek.com/guides/responses_api/)。[12][14][15][16]

## 5. 智谱 GLM 的 Anthropic 兼容

- Anthropic 兼容 base URL：`https://open.bigmodel.cn/api/anthropic`（国际服为 `https://api.z.ai/api/anthropic`），直接用 Anthropic SDK 换 base_url 和 api_key 即可[18][19]
- 对照的 OpenAI 兼容入口是 `https://open.bigmodel.cn/api/coding/paas/v4`（Coding Plan）或 `https://open.bigmodel.cn/api/v1`（Codex 场景），两者不要混用[20][21]

文档：[Claude API 兼容](https://docs.bigmodel.cn/cn/guide/develop/claude/introduction)、[接入工具（协议与 Base URL 对照表）](https://docs.bigmodel.cn/cn/guide/develop/others)。[18][22]

写适配层时最易踩的三个坑：Anthropic 没有 `system` role（系统提示必须走顶层字段）、Gemini 的助手角色叫 `model` 而非 `assistant`、DeepSeek 的 `reasoning_content` 在带工具调用时必须回传否则 400。
