# e005 — 核验群：终审从「对笔记抽查」改成「对原页逐条核验」

## 证据

- **e002/prompt-caching**（`ds/log.md` 终审段）：审稿工人抽查 44 条，42 supported / 2 weak / **0 contradicted**。但同一篇成稿在盲评里被点名 ≥4 条硬错（`judge/prompt-caching/*e000b*` 的 errors_y）：§0「DeepSeek、智谱写入不加价」vs 自家矩阵智谱 `∅`；§0「Kimi 1.25x 起」vs 矩阵「5m 档=标准价」；「OpenAI 旧款 0.5x」（GPT-5 系实为 0.1x，计费数字错）；「2025-03-13 Automatic Caching」功能描述张冠李戴。审稿全过 ≠ 没错。
- **e001/prompt-caching** `ds/audit.md`：34 条全 supported，其中「DeepSeek 小时到 24 小时量级」被判决点名——官方原话 "hours to days"，审稿工人把「笔记里有这句」当成 supported，没回原页核对字面。
- 四题判决的硬错集中在具体事实：字段名拼接（`usageMetadata.total_cached_tokens`，e000a/e000b 两侧多次）、版本起点（MCP 2024-10-07 vs 2024-11-05）、支持/不支持（Google×MCP 标 ❓、Anthropic 无独立框架、Poetry 不能装解释器）、计费数字。这些格子在 grid 里全是 `✅`，**e002 的反证只覆盖进一屏/疑点结论的边界主张**，其余 ✅ 格和坑节事实从未对原页核验过。
- 浪费面：审稿工人 1 spawn 抽 20–44 条对笔记，产出近乎全 supported——这层预算没买到任何纠错。

## 假设

把终审的 1 个审稿工人换成一簇「核验工人」：主 agent 先列核验清单（高杠杆主张 + 笔记摘录 + URL），按域名/实体聚簇派 ≤ workers 个工人**回原页**逐条判定，再按判定改稿。字段名/版本/计费/支持性这四类硬错会下降（accuracy、doubts 升），sourcing 不降（[n] 保留、URL 本来就在清单里）。核验不占扩展轮次（终审在最后一次收束之后、不算一轮），删掉旧审稿工人抵掉 1–2 spawn，净增 ~2–4 spawn。

分工：反证简报（轮内）管「还没进成稿的边界主张」，找反例；核验工人（终审）管「已成稿的高杠杆事实」，对原页；原审稿的「追不到来源就降级」并入主 agent 自查（硬规则已有）。改稿权始终在主 agent。

## 改动

- `SKILL.md`「终审与停止」重写为三步：① 列核验清单（挑选规则：§0 全条 + 疑点结论全条 + 坑节事实 + 被引用/⚔裁决/单源高影响矩阵格；排除轮内已反证的；一 URL 一判定项；按域名聚簇，每工人 ≤10 条，总数 ≤ workers，截断优先级 一屏>疑点>⚔>坑>矩阵，截掉的进 §5）；② 派核验工人拿判定表写 `audit.md`；③ 按判定改稿（wrong 须附页面原句才改、打不开只标「未核实」不删、走样改回摘录）；④ 收尾不变。
- `references/worker.md`：新增「核验简报模板」（判定项格式 + 四种判定口径；不写笔记、不调研）；工人规则加一条「核验简报只回判定表」。
- `agents/research-worker.md`：同步一条核验简报规则。
- `references/converge.md`：「审稿标准」整节换成「核验」改稿规则；标题同步。

## 预期变好的维度/指标

- `errors_x/errors_y` 中具体事实类减少 → accuracy、doubts 升；orientation/coverage 不变。
- spawns ~11 → ~14–16；单次成本约 +$1–2（远在在位者 1.5× 内）；核验工人每簇只开几页，比调研工人快，60min 上限风险小。
- `traceable` 不降：判定项自带 URL，改稿保留 [n]。

## 风险

- 核验工人误报 wrong → 要求附页面原句；附不上只按「未核实」降级，不采信口述改法。
- 页面打不开（如 Grok 臂被 SSRF 拦的域名）会产生误删 → 判定区分「打不开」与「打开了但没写」，前者不删。
- 截断漏核：装不下的主张只剩 [C#] 自查兜底，仍可能漏硬错——但比现在「全部没人对原页」强。
- 终审多派工人拉长尾段；若逼近 60min，成稿已存在，超时按当时 report.md 打分，损失有界。
