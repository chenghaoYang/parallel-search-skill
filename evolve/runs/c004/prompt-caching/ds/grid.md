# grid v0：实体 × 维度

## 分类轴（家族划分依据）
缓存机制谱系：A 全自动隐式（前缀命中，零代码改动）/ B 手动断点（用户打标记，平台据此缓存）/ C 显式缓存对象（先创建缓存资源再引用）/ D 网关透传（透传上游机制 + 自身计费归一）。

## 维度（每列回答的问题）
- D1 机制类型：自动 / 手动断点 / 显式对象？
- D2 触发方式：要改什么代码？字段名、枚举值、header。
- D3 最小门槛：最少多少 token 才缓存？哪些模型支持？
- D4 计费：缓存写入价、命中读取折扣、存储费（按 token·秒？）。
- D5 TTL：缓存存活多久？是否可配？是否刷新续期？
- D6 命中确认：响应里哪个字段表明命中（usage.xxx）。
- D7 失效条件：什么改动破缓存（前缀顺序、tools、system、消息任意位置改动）？粒度（前缀 vs 块级）？
- D8 可缓存内容：system / tools / images / 多轮消息，有什么限制。
