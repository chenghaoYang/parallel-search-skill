## claims
- [C1] `pdm add` writes PEP 508 requirements into PEP 621 `[project] dependencies`; local paths become `file:///${PROJECT_ROOT}/...` URLs | src: https://pdm-project.org/en/latest/usage/dependency/ | quote: "The local dependencies will be written to the `pyproject.toml` file with the URL format" | type: official
- [C2] `pdm add -G <name>` writes to `[project.optional-dependencies.<name>]`; `pdm add -d` writes to `[dependency-groups]` (PEP 735) `dev` group; same group name must not appear in both tables | src: https://pdm-project.org/en/latest/usage/dependency/ | quote: "The same group name MUST NOT appear in both `[dependency-groups]` and `[project.optional-dependencies]`" | type: official
- [C3] PEP 735 `[dependency-groups]` support added in v2.20.0 (2024-10-31), replacing legacy `[tool.pdm.dev-dependencies]` | src: https://github.com/pdm-project/pdm/blob/main/CHANGELOG.md | quote: "Support dependency groups as standardized by [PEP 735](https://peps.python.org/pep-0735/). By default, dev dependencies will be written to `[dependency-groups]` table." | type: official
- [C4] Editable deps only allowed in dev groups: `pdm add -e ./sub-package --dev`; other groups fail with `[PdmUsageError]` | src: https://pdm-project.org/en/latest/usage/dependency/ | quote: "Editable packages are allowed only in development dependencies" | type: official
- [C5] Two lock formats: `pdm` (default `pdm.lock`) and `pylock` (default `pylock.toml`); default is `pdm` | src: https://pdm-project.org/en/latest/usage/lockfile/ | quote: "PDM supports two lock file formats: `pdm`(default file name is `pdm.lock`) and `pylock`(default file name is `pylock.toml`). The default format is `pdm`." | type: official
- [C6] pylock = PEP 751 format, experimental since PDM 2.25.0 (2025-06-13); export supported since 2.24.0; switch via `pdm config lock.format pylock`; planned future default | src: https://pdm-project.org/en/latest/usage/lockfile/ | quote: "Added experimental support for the PEP 751 pylock file format. ... It is set to become the default in a future version of PDM." | type: official
- [C7] PEP 751 itself is Final/Standards Track and mandates `pylock.toml` (or `pylock.<name>.toml`) TOML files for reproducible installs | src: https://peps.python.org/pep-0751/ | quote: "A file format to record Python dependencies for installation reproducibility" | type: official
- [C8] `pdm.lock` is TOML: `[metadata]` with `groups`, `strategy`, `lock_version = "4.5.1"`, `content_hash`; `[[metadata.targets]]` with `requires_python`; `[[package]]` entries with `files = [{file=..., hash=...}]` | src: https://raw.githubusercontent.com/pdm-project/pdm/main/pdm.lock | quote: "[metadata]\ngroups = [\"default\", \"all\", \"doc\", \"keyring\", \"pytest\", \"test\", \"tox\", \"workflow\"]\nstrategy = [\"inherit_metadata\"]\nlock_version = \"4.5.1\"" | type: official
- [C9] Lock strategies include `cross_platform` (deprecated 2.17.0), `static_urls`, `direct_minimal_versions`, `inherit_metadata`; flags persisted in lockfile metadata | src: https://pdm-project.org/en/latest/usage/lockfile/ | quote: "The flags will be encoded in the lockfile and get read when you run `pdm lock` next time." | type: official
- [C10] `pdm python install` (added v2.13.0, 2024-03-27) installs interpreters from indygreg's python-build-standalone; `pdm python install --list`/`pdm python list`/`pdm python remove`; installs to `python.install_root` | src: https://pdm-project.org/en/latest/usage/project/ | quote: "PDM supports installing additional Python interpreters from @indygreg's python-build-standalone" | type: official
- [C11] Bare `pdm python install` picks best match for `requires-python` (v2.16.0+), default strategy `maximum` (highest cPython); `--min` picks lowest | src: https://pdm-project.org/en/latest/usage/project/ | quote: "Default strategy is `maximum`, i.e. the highest cPython interpreter version will be installed." | type: official
- [C12] Selected interpreter path stored in `.pdm-python`; changed via `pdm use`; `.python-version` file / `PDM_PYTHON_VERSION` respected since 2.23.0; `PDM_PYTHON` env var overrides | src: https://pdm-project.org/en/latest/usage/project/ | quote: "The interpreter path will be stored in `.pdm-python` and used by subsequent commands." | type: official
- [C13] Experimental workspace support added v2.28.0 (2026-06-23): `[tool.pdm.workspace] members = ["packages/foo", "tools/*"]`; members are implicit editable deps of root; single shared root lockfile; `install`/`lock`/`sync` run at root, `add`/`build`/`publish` can target members | src: https://pdm-project.org/en/latest/usage/workspace/ | quote: "PDM can manage a workspace made of a root project and multiple member projects under the same repository." | type: official
- [C14] Pre-workspace monorepo recipe (still documented): dev group entries `-e file:///${PROJECT_ROOT}/packages/foo-core`, members depend by name, one `pdm.lock`, all installed editable | src: https://pdm-project.org/en/latest/usage/advanced/ | quote: "you can have multiple sub-packages within a single project, each with its own `pyproject.toml` file ... create only one `pdm.lock` file to lock all dependencies" | type: official
- [C15] Build backend is `pdm-backend`: `requires = ["pdm-backend"]`, `build-backend = "pdm.backend"`; supports PEP 517/621/660; successor of `pdm-pep517`; usable standalone (`python -m build`) | src: https://backend.pdm-project.org/ | quote: "It is recommended to use PDM to manage your project, which will automatically generate the above configuration for you." | type: official
- [C16] Default backend switched to `pdm-backend` in v2.5.0 (2023-04-09); `pdm-pep517` removed in v2.9.0; `pdm init --backend` (setuptools/flit/hatchling/pdm-pep517) added v2.3.0 | src: https://github.com/pdm-project/pdm/blob/main/CHANGELOG.md | quote: "Switch the default build backend to `pdm-backend`. - [C17] `pdm build` produces wheel+sdist into `dist/`; `pdm publish` builds and uploads; `pdm publish --repository testpypi` or URL; API token auth `__token__`; trusted publishing supported (id-token) | src: https://pdm-project.org/en/latest/usage/publish/ | quote: "This will automatically build a wheel and a source distribution(sdist), and upload them to the PyPI index." | type: official
- [C18] venv is the default mode; PEP 582 is opt-in | src: https://pdm-project.org/en/latest/usage/venv/ | quote: "virtualenv is the default mode if not configured otherwise ... By default pdm is configured to use virtual environment instead of PEP 582" | type: official
- [C19] First `pdm install` auto-creates `<project_root>/.venv`; backends virtualenv (default)/venv/conda via `venv.backend`; `venv.in_project false` uses named venvs under `venv.location`; pip excluded by default (`venv.with_pip`) | src: https://pdm-project.org/en/latest/usage/venv/ | quote: "PDM will create a virtualenv in `<project_root>/.venv`, and install dependencies into it." | type: official
- [C20] `pdm config python.use_venv false` enables PEP 582 `__pypackages__` mode; auto-enabled if project has empty `__pypackages__`; `pdm --pep582` installs global sitecustomize; PEP 582 rejected but retained | src: https://pdm-project.org/en/latest/usage/pep582/ | quote: "This is a rejected PEP. ## conflicts
- None material. Minor version drift inside official docs: `setup-pdm` README main example pins `@v4` while its caching examples still show `@v3`; docs CI page shows `@v4`.

## gaps
- Docs "Use PDM in Continuous Integration" section itself contains no caching guidance (only a HOME-permission workaround); cache inputs are documented only in the setup-pdm action README.
- `pdm export` format list (`-f` choices beyond `pylock`) not enumerated on the pages checked.
- `uv.py`/`pylock.py` exist under `src/pdm/formats/` but are not registered in `FORMATS`; `pdm import` accepts only the 5 documented formats (pipfile, poetry, flit, setuppy, requirements).
- Exact lock_version history of `pdm.lock` (now "4.5.1") not traced.

## leads
- Experimental `use_uv` mode: PDM can use uv as resolver/installer, incl. workspace interop via generated `[tool.uv.sources]` (usage/uv.md).
- `pdm dockerize` (third-party plugin) supports PDM workspaces requiring pdm>=2.28: https://github.com/noirbizarre/pdm-dockerize/
- `pdm export -f pylock` conversion + alternate lockfiles via `-L/--lockfile` / `PDM_LOCKFILE` exist for split-lock workflows.
