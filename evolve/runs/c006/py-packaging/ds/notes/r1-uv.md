## claims
- [C1] uv 项目锁文件为 `uv.lock`（TOML，置于 pyproject.toml 旁），由 uv 管理、不可手改，格式为 uv 专有 | src: https://docs.astral.sh/uv/concepts/projects/layout/ | quote: "uv.lock is a human-readable TOML file but is managed by uv and should not be edited manually." | type: official
- [C2] uv.lock 是跨平台 universal 锁文件（覆盖所有 OS/架构/Python marker），由 `uv sync`/`uv run` 自动创建更新，可 `uv lock` 显式更新 | src: https://docs.astral.sh/uv/concepts/projects/layout/ | quote: "uv.lock is a _universal_ or _cross-platform_ lockfile" | type: official
- [C3] uv 支持导出 PEP 751 `pylock.toml`：`uv export --format pylock.toml`；export 格式有 requirements.txt / pylock.toml / cyclonedx1.5 | src: https://docs.astral.sh/uv/concepts/projects/export/ | quote: "`pylock.toml`: The standardized Python lockfile format defined in PEP 751." | type: official
- [C4] PEP 751 支持自 uv 0.6.15（发布于 2025-04-22）起为"preliminary"：可 `uv export -o pylock.toml` 导出、`uv pip compile -o pylock.toml` 生成、`uv pip sync pylock.toml` 或 `uv pip install -r pylock.toml` 安装 | src: https://github.com/astral-sh/uv/blob/main/changelogs/0.6.x.md | quote: "This release includes preliminary support for the `pylock.toml` file format, as standardized in PEP 751." | type: official
- [C5] `uv run --with-requirements` 可消费 pylock.toml | src: https://docs.astral.sh/uv/reference/cli/ | quote: "The following formats are supported: `requirements.txt`, `.py` files with inline metadata, and `pylock.toml`." | type: official
- [C6] 项目依赖声明用 PEP 621 `[project.dependencies]`；extras 用 `[project.optional-dependencies]` | src: https://docs.astral.sh/uv/concepts/projects/dependencies/ | quote: "are specified using dependency specifiers syntax, and the table follows the PEP 621 standard." | type: official
- [C7] 开发依赖用 PEP 735 `[dependency-groups]`；旧字段 `tool.uv.dev-dependencies` 将被废弃移除 | src: https://docs.astral.sh/uv/concepts/projects/dependencies/ | quote: "uv uses the `[dependency-groups]` table (as defined in PEP 735) for declaration of development dependencies." | type: official
- [C8] `uv add` / `uv remove` 修改依赖，可用 `--dev`、`--group`、`--optional` 指定目标字段 | src: https://docs.astral.sh/uv/concepts/projects/dependencies/ | quote: "The `--dev`, `--group`, or `--optional` flags can be used to add dependencies to an alternative field." | type: official
- [C9] `tool.uv.sources` 声明依赖的替代来源（index/git/URL/path/workspace），仅开发期生效 | src: https://docs.astral.sh/uv/concepts/projects/dependencies/ | quote: "`tool.uv.sources`: Alternative sources for dependencies during development" | type: official
- [C10] workspace：在 pyproject.toml 加 `[tool.uv.workspace]`，`members`（必填，glob 列表）+ `exclude`（可选）；根包本身也是 member | src: https://docs.astral.sh/uv/concepts/projects/workspaces/ | quote: "Every workspace needs a root, which is _also_ a workspace member." | type: official
- [C11] workspace 全成员共享单一锁文件：`uv lock` 对整个 workspace 操作；成员间依赖经 `tool.uv.sources` 中 `workspace = true` 声明且为 editable；强制全 workspace 单一 requires-python（取交集） | src: https://docs.astral.sh/uv/concepts/projects/workspaces/ | quote: "Dependencies between workspace members are editable." | type: official
- [C12] uv 可自行安装管理 Python：`uv python install 3.12`（支持约束、多版本、pypy），默认需要时自动下载；CPython 用 Astral python-build-standalone 预编译发行版 | src: https://docs.astral.sh/uv/concepts/python-versions/ | quote: "By default, uv will automatically download Python versions when needed." | type: official
- [C13] 自带构建后端 `uv_build`：`[build-system] requires = ["uv_build>=0.12.18,<0.13"]`，`build-backend = "uv_build"`；默认 `src/<package_name>/__init__.py` 布局；仅支持纯 Python（扩展模块需换后端，官方建议 hatchling）；`uv build` 产 sdist+wheel | src: https://docs.astral.sh/uv/concepts/build-backend/ | quote: "The uv build backend currently only supports pure Python code." | type: official
- [C14] `uv venv` 创建 `.venv`；uv pip 系命令环境查找顺序：VIRTUAL_ENV → CONDA_PREFIX → 就近 `.venv` | src: https://docs.astral.sh/uv/pip/environments/ | quote: "A virtual environment at `.venv` in the current directory, or in the nearest parent directory." | type: official
- [C15] 项目环境为 pyproject.toml 旁的 `.venv` 目录，`uv sync` 显式创建、`uv run` 自动创建并保证最新；不应入版本库 | src: https://docs.astral.sh/uv/concepts/projects/layout/ | quote: "The project environment can also be explicitly created with `uv sync`" | type: official
- [C16] 官方迁移指南目前只有「pip → uv 项目」一篇；从其他项目管理工具或 pip→`uv pip` 的指南尚未编写（issue #5200） | src: https://docs.astral.sh/uv/guides/migration/ | quote: "Other guides, such as migrating from another project management tool, or from pip to `uv pip` are not yet available." | type: official
- [C17] `uv add -r requirements.txt` 可直接导入 requirements 文件依赖 | src: https://docs.astral.sh/uv/concepts/projects/dependencies/ | quote: "Dependencies declared in a `requirements.txt` file can be added to the project with the `-r` option" | type: official
- [C18] 第三方 `migrate-to-uv`（uvx 可跑）支持从 Poetry（含 PEP 621 的 Poetry 2.0+）/Pipenv/pip-tools/pip 迁移，并保留锁定版本生成 uv.lock | src: https://github.com/mkniewallner/migrate-to-uv | quote: "Poetry (including projects using PEP 621 in Poetry 2.0+) - Pipenv - pip-tools - pip" | type: secondary
- [C19] GitHub Action `astral-sh/setup-uv` 内置缓存：`enable-cache`（默认 `"auto"`，GitHub 托管 runner 自动开）、`cache-dependency-glob`（默认含 `**/uv.lock`、`**/pyproject.toml`、requirements/constraints glob）、`cache-suffix`、`prune-cache` | src: https://github.com/astral-sh/setup-uv | quote: "Enable the GitHub Actions cache for uv: true, false, or auto" | type: official
- [C20] 手动缓存：设 `UV_CACHE_DIR` 后用 actions/cache，键示例 `uv-${{ runner.os }}-${{ hashFiles('uv.lock') }}`；`uv cache prune --ci` 精简缓存 | src: https://docs.astral.sh/uv/guides/integration/github/ | quote: "The `uv cache prune --ci` command is used to reduce the size of the cache and is optimized for CI." | type: official
- [C21] 私有源：`[[tool.uv.index]]`（name+url）配多个 index，`default = true` 替换 PyPI、`explicit = true` 仅钉选包可用；包可用 `tool.uv.sources` 的 `index = "name"` 钉到指定 index；默认 first-index 策略（防依赖混淆），另有 unsafe-first-match/unsafe-best-match | src: https://docs.astral.sh/uv/concepts/indexes/ | quote: "uv will stop at the first index on which a given package is available" | type: official
- [C22] pip 兼容选项：`--index-url` 映射到 `--default-index`、`--extra-index-url` 映射到 `--index`；env 变量 `UV_INDEX`/`UV_DEFAULT_INDEX` | src: https://docs.astral.sh/uv/concepts/indexes/ | quote: "`--index-url` maps to `--default-index`, and `--extra-index-url` maps to `--index`." | type: official
- [C23] 私有源认证按优先级：URL 内嵌凭据 → .netrc（`NETRC` env 或 ~/.netrc，始终启用）→ `uv auth` 凭据存储（预览后端 `UV_PREVIEW_FEATURES=native-auth`）→ keyring（`--keyring-provider subprocess`/`UV_KEYRING_PROVIDER`）；index 凭据不会写入 pyproject.toml/uv.lock | src: https://docs.astral.sh/uv/concepts/authentication/http/ | quote: "Reading credentials from .netrc files is always enabled" | type: official

## conflicts
- 无硬冲突。轻微表述差：0.6.15 changelog 称 pylock.toml 支持为 "preliminary"，而现行 export 文档页不给 pylock.toml 标 preview（只给 CycloneDX 标 preview），说明已转正——两页并不矛盾。

## gaps
- `uv sync`/`uv lock` 能否把 pylock.toml 当项目主锁文件：文档显示项目锁仍是 uv.lock，pylock 消费路径只有 `uv pip`/`uv run --with-requirements`/`uv pip compile`，但无页面明说「uv sync 不支持 pylock」——按现行文档视为不支持，未找到反例（查过 export 页、cli ref、0.6–0.12 changelog）。
- 按 index 的凭据 env 变量（如 `UV_INDEX_<NAME>_USERNAME`/`_PASSWORD`）在 http auth 页未见，指向 "index authentication documentation" 子页未取。
- GitLab CI / Docker 的 uv 缓存指南未取（在 integration/gitlab、integration/docker）。
- workspace 成员是否必须各自带 `[build-system]`：workspaces 页未明说。

## leads
- Q1 另一半（pip 是否支持 PEP 751）需由 pip worker 确认；uv 侧已双向支持（0.6.15 起，export+install）。
- `uv auth` CLI（login/token 凭据存储）为较新功能，native-auth 存储仍在 preview。
- `centralized-project-envs` preview 功能可把项目 .venv 集中到缓存目录。
