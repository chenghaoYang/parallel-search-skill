# r1-agui
question: AG-UI (Agent-User Interaction Protocol, CopilotKit) 的规格：连接哪两端、治理方、传输、事件模型、鉴权、版本、与 MCP/A2A 的关系、代表集成。
checked: https://docs.ag-ui.com/introduction, https://github.com/ag-ui-protocol/ag-ui, https://docs.ag-ui.com/concepts/events, https://docs.ag-ui.com/concepts/architecture, https://docs.ag-ui.com/agentic-protocols, https://docs.ag-ui.com/spec/1.0/schema.json (via https://ag-ui.com redirect), https://raw.githubusercontent.com/ag-ui-protocol/ag-ui/main/spec/README.md, https://raw.githubusercontent.com/ag-ui-protocol/ag-ui/main/spec/1.0/proto-freeze.txt, https://registry.npmjs.org/@ag-ui%2fcore, https://www.copilotkit.ai/blog/introducing-ag-ui-the-protocol-where-agents-meet-users, https://www.copilotkit.ai/blog/big-updates-on-ag-ui

## claims
- [C1] AG-UI connects agent backends to user-facing frontends; it is "an open, lightweight, event-based protocol that standardizes how AI agents connect to user-facing applications" and "the general-purpose, bi-directional connection between a user-facing application and any agentic backend." | src: https://docs.ag-ui.com/introduction | quote: "an open, lightweight, event-based protocol that standardizes how AI agents connect to user-facing applications" | type: official
- [C2] Created by CopilotKit; public announcement blog post dated May 12, 2025; docs state it was "born from CopilotKit's initial partnership with LangChain and CrewAI." | src: https://www.copilotkit.ai/blog/introducing-ag-ui-the-protocol-where-agents-meet-users | quote: "We're thrilled to announce AG-UI, the Agent-User Interaction Protocol" | type: official
- [C3] Governance: lives under github.com/ag-ui-protocol org, MIT licensed ("AG-UI is open source software licensed as MIT"), community input via a "Biweekly AG-UI Working Group" and public roadmap/CONTRIBUTING.md; no foundation named. | src: https://github.com/ag-ui-protocol/ag-ui | quote: "AG-UI is open source software licensed as MIT" | type: official
- [C4] Transport-agnostic: "supporting various transport mechanisms including Server-Sent Events (SSE), webhooks, WebSockets, and more"; reference HttpAgent uses HTTP POST with body RunAgentInput and returns a stream of BaseEvent; also offers an "HTTP binary protocol" (protobuf slots ledgered in spec/1.0/proto-freeze.txt). | src: https://docs.ag-ui.com/concepts/architecture | quote: "supporting various transport mechanisms including Server-Sent Events (SSE), webhooks, WebSockets, and more" | type: official
- [C5] Client contract: HttpAgent "accepts POST requests with a body of type RunAgentInput and sends a stream of BaseEvent objects"; core abstraction is run(input: RunAgentInput) -> Observable<BaseEvent>. | src: https://docs.ag-ui.com/concepts/architecture | quote: "accepts POST requests with a body of type RunAgentInput and sends a stream of BaseEvent objects" | type: official
- [C6] Event model: 31 active event types in spec 1.0 EventType enum (verified directly in schema.json), grouped in docs as Lifecycle 5 (RUN_STARTED, RUN_FINISHED, RUN_ERROR, STEP_STARTED, STEP_FINISHED), Text Message 4 (TEXT_MESSAGE_START/CONTENT/END/CHUNK), Tool Call 5 (TOOL_CALL_START/ARGS/END/RESULT/CHUNK), State Management 3 (STATE_SNAPSHOT, STATE_DELTA, MESSAGES_SNAPSHOT), Activity 2 (ACTIVITY_SNAPSHOT/DELTA), Reasoning 7 (REASONING_*), Special 2 (RAW, CUSTOM), Subagent 3 (SUBAGENT_STARTED/FINISHED/ERROR); plus 1 draft (META_EVENT) and 5 deprecated THINKING_*. | src: https://docs.ag-ui.com/concepts/events + https://docs.ag-ui.com/spec/1.0/schema.json | quote: "the `RunStarted` and either `RunFinished` or `RunError` events are mandatory, forming the boundaries of an agent run" | type: official
- [C7] Middleware/bridging: "The protocol includes a built-in middleware layer that maximizes compatibility"; "Events don't need to match AG-UI's format exactly—they just need to be AG-UI-compatible." | src: https://docs.ag-ui.com/concepts/architecture | quote: "Events don't need to match AG-UI's format exactly—they just need to be AG-UI-compatible" | type: official
- [C8] Auth: spec defines no authentication mechanism — schema.json (98 defs) contains zero auth/authorization/bearer/apiKey/oauth fields; docs architecture page mentions only a "Secure Proxy" backend component. CopilotKit blog lists enterprise concerns handled at deployment level: "It works with enterprise needs (CORS, auth tokens, audit logging) out of the box." | src: https://docs.ag-ui.com/spec/1.0/schema.json + https://www.copilotkit.ai/blog/ag-ui-protocol-bridging-agents-to-any-front-end | quote: "It works with enterprise needs (CORS, auth tokens, audit logging) out of the box" | type: official
- [C9] Versioning: machine-readable spec is JSON Schema at $id https://ag-ui.com/spec/1.0/schema.json (served from docs.ag-ui.com/spec/1.0/schema.json); @ag-ui/core npm reached 1.0.0 on 2026-09-17 (package created 2025-04-30, 76 versions); repo uses date-based release tags (e.g. release/2026-09-23); RunAgentInput and RunStarted carry a protocolVersion field. | src: https://registry.npmjs.org/@ag-ui%2fcore + https://docs.ag-ui.com/spec/1.0/schema.json | quote: "\"$id\": \"https://ag-ui.com/spec/1.0/schema.json\"" | type: official
- [C10] Relation to MCP/A2A — complementary layers: MCP "Connects agents to tools and to context", A2A "Connects agents to other agents", AG-UI "Connects agents to users (through user-facing applications)"; "These three agentic protocols are complementary and have distinct technical goals"; AG-UI can "'front for' agents through MCP and A2A protocols." | src: https://docs.ag-ui.com/agentic-protocols | quote: "These three agentic protocols are complementary and have distinct technical goals" | type: official
- [C11] Integrations (per repo README status table): Supported — LangGraph (partnership), CrewAI (partnership), Microsoft Agent Framework, Google ADK, AWS Strands Agents, Mastra, Pydantic AI, Agno, LlamaIndex, AG2, Claude Agent SDK, Langroid; plus protocol bridges A2A, Amazon Bedrock AgentCore, Oracle Agent Spec, MCP Apps; In Progress — OpenAI Agent SDK, Cloudflare Agents, AWS Bedrock Agents. SDKs: TS/Python first-party; Kotlin, Go, Dart, Java, Rust, Ruby, C++, .NET community. Clients: CopilotKit, terminal, Slack/Teams, React Native. | src: https://github.com/ag-ui-protocol/ag-ui | quote: "emit events _compatible_ with one of AG-UI's ~16 standard event types" | type: official
- [C12] Compatibility rule: "Exact objects, forgiving receivers" — schema objects closed via unevaluatedProperties:false; receivers must tolerate/strip unknown fields with warning rather than reject (cross-version compat is receiver behavior, not validation). | src: https://raw.githubusercontent.com/ag-ui-protocol/ag-ui/main/spec/README.md | quote: "an SDK boundary tolerates fields it does not recognise — stripping them with a warning rather than rejecting the stream" | type: official
- [C13] RunAgentInput fields: required [threadId, runId, messages]; optional state, tools, context, forwardedProps, parentRunId, protocolVersion, resume. | src: https://docs.ag-ui.com/spec/1.0/schema.json | quote: "\"required\": [\"threadId\", \"runId\", \"messages\"]" | type: official
- [C14] Repo traction: ~16k stars, 1.4k forks, 4,137 commits (README badges, fetched 2026-09-25); CopilotKit is "a first-class client to the protocol." | src: https://github.com/ag-ui-protocol/ag-ui + https://www.copilotkit.ai/blog/introducing-llamaindex-integration-with-copilotkit | quote: "CopilotKit is a first-class client to the protocol" | type: official

## conflicts
- Event count: repo README still says "~16 standard event types" (true at May 2025 launch; blog repeats "one of 16 events") while spec 1.0 EventType enum now lists 31 active types. README lags the 1.0 spec.
- Docs events page said deprecated THINKING_* events "will be removed in version 1.0.0" — confirmed removed: no THINKING_* in the 1.0 EventType enum.

## gaps
- Exact original launch date of protocol vs first npm publish (2025-04-30) vs announcement post (2025-05-12); no single canonical "launch" statement found.
- No formal governance charter/foundation found; "Biweekly AG-UI Working Group" is the only governance mechanism named.
- Whether the binary protobuf transport is fully documented publicly (proto-freeze.txt exists in repo; no docs page found).
