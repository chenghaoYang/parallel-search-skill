## conflicts
- ACP 缩写三方撞车（最大坑）: IBM/BeeAI "Agent Communication Protocol"（已并入 A2A）vs AGNTCY "Agent Connect Protocol" vs OpenAI/Stripe "Agentic Commerce Protocol"——同名不同物，文档/帖子里必须消歧。
- Stripe docs 称 ACP "created by Stripe, OpenAI, and Meta"（https://docs.stripe.com/agentic-commerce/acp），而 agenticcommerce.dev 只说 "Stripe and OpenAI developed the Agentic Commerce Protocol"——Meta 是否共同创立者两说。
- agent.json vs agent-card.json：旧教程/SDK 用 agent.json，v0.3.0 起官方是 agent-card.json（见 C7）。

## gaps
- AG-UI 是否后续加入 AAIF：LF 公告只列 MCP/goose/AGENTS.md 为 founding projects，未提 AG-UI；A2A 早在 AAIF 之前已在 LF——注意 "LF 旗下" ≠ AAIF。
- AGNTCY ACP 现状（是否仍在维护、与 A2A 的关系）未核实；只看到 spec repo 存在。
- MCP Apps 的 spec 状态（SEP 编号、是否已合并进 spec）未核实，仅有 OpenAI 博客提及。
- OAuth 2.1 落地痛点（DCR 不普及、token passthrough 禁令影响代理服务器）只有 spec 条文，无用户抱怨一手来源。
- ANP/UTCP 实际采用度未知；ANP 主页未署名组织。

## leads
- 电商/支付协议汤：ACP(comm) vs UCP vs AP2 vs x402 (Coinbase HTTP 402)——用户极易混；UCP 自称兼容 A2A/AP2/MCP。
- UI 层协议汤：AG-UI vs A2UI vs MCP Apps (ex-MCP-UI) vs OpenAI ChatKit/Apps SDK——"谁渲染、谁传输"是常见混淆点；Google 官方说 A2UI payload 可走 A2A/AG-UI，AG-UI 客户端即兼容 A2UI。
- NLWeb (Microsoft)、NLIP (Ecma)、agents.json 提案——agent-facing web 标准的长尾。
- OpenAPI→MCP 代码生成（Stainless/Speakeasy）与 UTCP "extends OpenAPI" 是 "OpenAPI-based tool 协议" 格子的来源。
- "AG-UI over A2A over MCP" 分层说法有官方出处（AG-UI README 三层定位），但严格说 A2UI/MCP Apps 都能横穿这几层，别把分层说成唯一正解。
