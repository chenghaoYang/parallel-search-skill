## conflicts
- 主张 A「Temporal 官方文档无 exactly-once 承诺」被推翻：docs.temporal.io/temporal、/activity-definition、/nexus/operations 三处一手页面均有 exactly-once 承诺（C1–C3）。注意限定语义：Activity 是 "observed as completed exactly once"（执行可多次）；Workflow 的 "exactly once and to completion" 指 durable-execution 语义；Nexus exactly-once 需 RejectDuplicates。搜索另命中 /handling-messages（"processed exactly once"）与 /workflow-streams（"exactly-once publishing"），未逐页复核。
- 主张 B「Inngest 官方文档不用 exactly-once/at-least-once 措辞」被推翻：reference/typescript/v4/functions/metadata 与 examples/durable-endpoints 均含 "exactly once"（C7–C8）。措辞用于 step 级 memoization，非整体投递语义。
- 主张 C 的严格措辞需加限定：停机错过不补跑成立（C9、C10、C12 无 backfill），但 v0.105.2 的 workflow pause QUEUE 选项会让暂停期 cron tick 排队并在 unpause 后重放（C11、C13）——这是"不错过"的排队机制而非错过后的补跑，若成稿表述为"任何错过的 tick 都不执行"则与 QUEUE 模式冲突。
- URL 变更：docs.hatchet.run/cron-runs 现 404，同文迁至 /v1/cron-runs（原句逐字保留）；docs.hatchet.run/changelog 404，正式 changelog 在 /reference/changelog/platform。
