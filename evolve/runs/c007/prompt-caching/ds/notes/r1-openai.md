# r1-openai

## claims
- [C1] Prompt caching 默认开启，无需任何参数即自动工作（implicit 模式）。 | src: https://developers.openai.com/api/docs/guides/prompt-caching | quote: "Prompt caching is enabled by default for supported OpenAI models." | type: official
- [C2] GPT-5.6 之前模型仅支持 implicit caching，断点由 OpenAI 按模型相关间隔自动放置；cookbook 亦确认"无需改 completions 请求"。 | src: https://developers.openai.com/api/docs/guides/prompt-caching | quote: "Only implicit caching is supported. OpenAI places implicit breakpoints at model-dependent intervals" | type: official
- [C3] GPT-5.6+ 新增显式控制：`prompt_cache_options.mode`（implicit|explicit）、内容块上加 `prompt_cache_breakpoint: {"mode":"explicit"}` 标记断点，每请求最多 4 个 cache write；`prompt_cache_options.prewarm` 可预热缓存；`prompt_cache_options.ttl` 控制寿命。 | src: https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create | quote: "Options for prompt caching. Supported for gpt-5.6 and later models. ... Each request can write up to four breakpoints." | type: official
- [C4] 最小可缓存前缀：GPT-5.6+ 为 1,024 visible input tokens；更早模型"varies by request settings"（含 tools、images、output schemas、reasoning effort、verbosity）；OpenAI 隐藏 system tokens 不计入。 | src: https://developers.openai.com/api/docs/guides/prompt-caching | quote: "The minimum cacheable prompt length is 1,024 tokens for GPT-5.6 and later and varies by request settings for earlier models." | type: official
- [C5] 5.6 前模型粒度：implicit breakpoints 按模型相关间隔放置（GPT-5.5 为固定 2,048-token 间隔）；上报 cached_tokens 会"rounding down to the nearest multiple of 128"；cookbook 称命中按 128 token 递增、1024 token 起。 | src: https://developers.openai.com/cookbook/examples/prompt_caching_201 | quote: "works automatically for prompts containing 1024 tokens or more, with cache hits occurring in increments of 128 tokens" | type: official
- [C6] GPT-5.6+ 计费：cache write = 1.25× 普通 input 价，cache read = 0.1×；例 gpt-6-sol input $2.00 / cached $0.20 / write $2.50 per 1M。 | src: https://developers.openai.com/api/docs/guides/prompt-caching | quote: "cache writes cost 1.25× the standard, uncached input-token rate... subsequent reads cost only 0.1× that rate" | type: official
- [C7] 更早模型无 cache-write 费，cached input 为模型相关折扣价（"discounted up to 90%"）：gpt-5/gpt-5.1 $1.25→$0.125（90% off），gpt-5.2 $1.75→$0.175，gpt-5.5 $5.00→$0.50，gpt-4.1 $2.00→$0.50（75%），gpt-4o $2.50→$1.25（50%），gpt-4o-mini $0.15→$0.075，o1 $15→$7.50，o3 $2.00→$0.50，o4-mini $1.10→$0.275（per 1M，standard tier）。 | src: https://developers.openai.com/api/docs/pricing | quote: "| gpt-4.1 | $2.00 | $0.50 | - | $8.00 |" | type: official
- [C8] TTL：GPT-5.6+ `prompt_cache_options.ttl` 唯一支持值 "30m"（默认）；命中会刷新寿命："reusing the prefix refreshes its lifetime without another cache-write charge"；"remains eligible for reuse for 30 minutes after its most recent write or reuse"。 | src: https://developers.openai.com/api/docs/guides/prompt-caching | quote: "A cached prefix remains eligible for reuse for 30 minutes after its most recent write or reuse, though OpenAI may retain it longer." | type: official
- [C9] 更早模型用 `prompt_cache_retention`（GPT-5.6+ 上已 deprecated）：`in_memory` 不活跃 5–10 分钟失效、最长 1 小时；`24h` 典型可用约 30 分钟、最长 24 小时。默认取决于 ZDR：非 ZDR 组织默认 24h，ZDR 组织默认 in_memory；gpt-5.5/5.5-pro 仅支持 24h。 | src: https://developers.openai.com/api/docs/guides/prompt-caching | quote: "`in_memory`: Entries typically remain active for around 5 to 10 minutes of inactivity, up to one hour. `24h`: ... can retain them for up to 24 hours." | type: official
- [C10] 命中确认字段：Responses API 为 `usage.input_tokens_details.cached_tokens` 和 `cache_write_tokens`；Chat Completions 为 `usage.prompt_tokens_details.cached_tokens`（"Cached tokens present in the prompt"）与 `cache_write_tokens`（"The unadjusted number of prompt tokens written to cache"）。 | src: https://developers.openai.com/api/docs/guides/prompt-caching | quote: "Track `usage.input_tokens_details.cached_tokens`, `usage.input_tokens_details.cache_write_tokens`" | type: official
- [C11] 失效条件：要求"the entire rendered prefix to match"；影响前缀的设置含 model、tools（names/descriptions/schemas/ordering）、parallel_tool_calls、text.format、reasoning.effort、text.verbosity、context_management(compaction)；任一变化后"the prefix after that change cannot match the existing cache entry"。 | src: https://developers.openai.com/api/docs/guides/prompt-caching | quote: "Cache reuse requires the entire rendered prefix to match." | type: official
- [C12] 路由层面：缓存在单台机器上，命中需请求落到持该前缀的机器；路由按"hash of the initial tokens after the hidden OpenAI content, including tool definitions"（cookbook 称 ~256 tokens）；每 prefix+key 约 15 RPM，超出会 overflow 到其他机器产生新 cache miss；`prompt_cache_key`（5.6 前）提高 stickiness 但不保证命中（示例 60%→87%）；缓存不跨组织、不跨区域边界。 | src: https://developers.openai.com/api/docs/guides/prompt-caching | quote: "Cached states live on individual machines, where traffic above 15 requests per minute can lead to overflow routing." | type: official
- [C13] 模型范围：cookbook 称"Prompt Caching is enabled for all recent models, gpt-4o and newer"；extended(24h) retention 支持 gpt-5.5, gpt-5.5-pro, gpt-5.4, gpt-5.2, gpt-5.1-codex-max, gpt-5.1, gpt-5.1-codex, gpt-5.1-codex-mini, gpt-5.1-chat-latest, gpt-5, gpt-5-codex, gpt-4.1。 | src: https://developers.openai.com/api/docs/guides/prompt-caching | quote: "Extended retention is supported by `gpt-5.5`, `gpt-5.5-pro`, `gpt-5.4`, `gpt-5.2`, `gpt-5.1-codex-max`, `gpt-5.1`, ... and `gpt-4.1`." | type: official
- [C14] 端点差异：Responses 与 Chat Completions 均支持 prompt_cache_key/retention/options/breakpoint（CC create 参考含全部四个参数）；Responses 对 reasoning 模型缓存利用率高 40–80%（CoT token 经 previous_response_id 持久化）；Batch API 对 pre-GPT-5 模型不支持缓存（pricing 表 Batch 栏 gpt-4.1/gpt-4o/o1/o3/o4-mini cached 均为 "-"）。 | src: https://developers.openai.com/cookbook/examples/prompt_caching_201 | quote: "There isn't model parity for caching on the Batch API - pre-GPT-5 models are not supported" | type: official
- [C15] pro 系列无缓存计价：gpt-5-pro, gpt-5.2-pro, gpt-5.4-pro, gpt-5.5-pro, o1-pro, o3-pro 的 cached input 列均为 "-"；Realtime 模型有 cached 价（gpt-realtime audio $32→$0.40）。 | src: https://developers.openai.com/api/docs/pricing | quote: "| gpt-5-pro | $15.00 | - | - | $120.00 |" | type: official
- [C16] 无手动清缓存；cached tokens 仍计入 TPM rate limit。 | src: https://developers.openai.com/api/docs/guides/prompt-caching | quote: "Manual cache clearing is not currently available." / "Cached input tokens still count toward tokens-per-minute limits." | type: official
- [C17] 诊断：Responses API（GPT-5.6+）支持 `prompt_cache_options.comparison_response_id` + 响应上 `prompt_cache_diagnostics`（type: cache_hit/cache_miss, reason 枚举如 tools_changed/input_changed/context_compacted）；Prompt Caching Dashboard 2026-08-20 上线。 | src: https://developers.openai.com/api/docs/guides/prompt-caching/diagnostics | quote: "Diagnostics are available in the Responses API for GPT-5.6 and later supported models." | type: official
- [C18] 时间线：prompt caching 2024-10 上线；extended retention(24h) 2025-11-13 发布；2026-05-29 起非 ZDR 组织默认 24h；GPT-5.6（2026-07-09）引入显式缓存控制与 cache-write 计费；diagnostics 2026-09-08 GA。 | src: https://developers.openai.com/api/docs/changelog | quote: "GPT-5.6 adds ... explicit prompt caching controls" | type: official
- [C19] 图像/音频/工具/structured output schema 均计入可缓存前缀；图像须完全一致且 detail 参数会影响 tokenization。 | src: https://developers.openai.com/cookbook/examples/prompt_caching101 | quote: "Images—whether linked or encoded in base64 within user messages—qualify for caching. Make sure the detail parameter remains consistent" | type: official

## conflicts
- 最小门槛表述不一：cookbook（标注仅适用 pre-5.6）称固定 "1024 tokens or more"，当前 guide 称 earlier models "varies by request settings"（tools/images/schemas/effort/verbosity 都会改变阈值），未给出逐模型数值表。
- prompt_cache_key 定位变化：guide 称 GPT-5.6+ "the key is not needed to optimize caching"（仅用于分账），而 pre-5.6 是命中优化关键手段——同一参数两代语义不同，非矛盾但易误读。

## gaps
- earlier models 逐模型的 minimum cacheable length 未列出具体数值（文档只说 varies + 隐藏 token 不计）。
- o1-preview / o1-mini / gpt-4.5-preview 等老模型当前是否仍支持缓存：pricing 页已不列出，未单独核实。
- extended retention 下"约 30 分钟典型"与 in_memory 的实际命中率差异无官方数字。

## leads
- Azure OpenAI 有平行文档（learn.microsoft.com azure/foundry prompt-caching），字段相同但默认/模型清单略有差异。
- cookbook 201 实测：Flex+extended+key 比 Batch 命中率 +8.5%、input 成本 -23%；prompt_cache_key 防跨用户 cache-hit probing。
- Prompt cache diagnostics 的 miss reason 枚举（model_changed/prompt_cache_key_changed/tools_changed/input_changed 等）可直接用于 D6 细化。
