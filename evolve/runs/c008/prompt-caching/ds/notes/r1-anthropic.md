## claims
- [C1] 现有两种启用方式：automatic caching = 在请求顶层加一个 `cache_control` 字段，系统自动把断点打到最后一个可缓存 block 并随对话前移；explicit = 逐 block 打 `cache_control` | src: https://platform.claude.com/docs/en/build-with-claude/prompt-caching | quote: "Add a single `cache_control` field at the top level of your request. The system automatically applies the cache breakpoint to the last cacheable block and moves it forward as conversations grow." | type: official
- [C2] automatic caching 于 2026-02-19 上线，官方称「无需手动断点管理」；即「必须手动打 cache_control」已不再成立（但仍需显式加一个顶层字段来启用，非默认开启） | src: https://platform.claude.com/docs/en/release-notes/overview | quote: "We've launched **automatic caching** for the Messages API. Add a single `cache_control` field to your request body and the system automatically caches the last cacheable block, moving the cache point forward as conversations grow. No manual breakpoint management required." | type: official
- [C3] 缓存以前缀为单位，顺序固定为 tools → system → messages，直到含 cache_control 的 block 为止 | src: https://platform.claude.com/docs/en/build-with-claude/prompt-caching | quote: "Prompt caching references the entire prompt: `tools`, `system`, and `messages` (in that order), up to and including the block designated with `cache_control`." | type: official
- [C4] 可缓存 block：tools 数组、system 数组、messages.content 中 user/assistant 的 text、user turn 的 images/documents、tool_use 与 tool_result；thinking block 不能直接打 cache_control（但随前文 assistant turn 一起被缓存），citations 子 block 与空 text block 不可缓存 | src: https://platform.claude.com/docs/en/build-with-claude/prompt-caching | quote: "Tools: Tool definitions in the `tools` array ... - [C5] SDK 的 beta 前缀已废弃，prompt caching 不再需要 beta header（`client.beta.prompt_caching.messages.create` → `client.messages.create`） | src: https://platform.claude.com/docs/en/build-with-claude/prompt-caching | quote: "Prompt caching no longer requires the beta prefix." | type: official

## conflicts
- automatic caching 可用范围随时间扩大：2026-02-19 changelog 称「Available on the Claude API and Microsoft Foundry (preview)」，现行文档称除 legacy Bedrock 外所有平台可用（含 Google Cloud、Claude Platform on AWS）。属扩展而非矛盾，但引用范围时以现行文档为准。

## leads
- cache diagnostics（`diagnostics` object，曾用 `cache-diagnosis-2026-04-07` beta header，2026-09 已 GA）：API 对比连续请求并报告前缀分歧点（cache_miss_reason）——排障「为什么没命中」的官方工具。
- mid-conversation system messages（`{"role":"system"}` 插入 messages）与 `inline-tools-2026-09-15` beta 可在不破坏缓存的情况下改指令/加工具。
