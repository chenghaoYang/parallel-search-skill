## claims
- [C1] pixi.toml 是 workspace manifest（TOML）；也支持 pyproject.toml，但表名须加 tool.pixi 前缀 | src: https://pixi.prefix.dev/latest/reference/pixi_manifest/ | quote: "you need to prepend the tables with `tool.pixi` instead of just the table name" | type: official
- [C2] pixi manifest 采用 TOML 1.1，但官方警告多数 Python 工具只读 TOML 1.0，在 pyproject.toml 中用 1.1 语法可能破坏其它工具 | src: https://pixi.prefix.dev/latest/reference/pixi_manifest/ | quote: "most Python tooling only reads TOML 1.0" | type: official
- [C3] [workspace] 表最小需 channels/platforms（name 默认取目录名）；channels 接受 anaconda.org 名、file:/// 路径或完整 URL；platforms 可为 `{ platform = "linux-64", cuda = "12.0" }` 形式钉虚拟包 | src: https://pixi.prefix.dev/latest/reference/pixi_manifest/ | quote: "Defines the list of platforms that the workspace supports." | type: official
- [C4] [dependencies] 是 conda 依赖（conda VersionSpec/matchspec）；[constraints] 只限制不强制引入；[pypi-dependencies] 走 uv 解析，支持 PEP440 version/extras/git/path/editable/url；[pypi-options] 有 index-url/extra-index-urls/find-links/no-build-isolation 等 | src: https://pixi.prefix.dev/latest/reference/pixi_manifest/ | quote: "Add any conda package dependency that you want to install into the environment." | type: official
- [C5] pixi.lock 记录 "the packages, their versions, and other metadata"，含 environments 段（每平台包 URL）与 version 字段（如 version: 6）；YAML、"built for machines, and made human readable"，不可手改 | src: https://pixi.prefix.dev/latest/workspace/lock_file/ | quote: "built for machines, and made human readable for easy inspection" | type: official
- [C6] pixi 为 manifest 里所有 environments 和 platforms 求解 → 单锁文件跨平台；"sharing a lock file can be done instead of sharing a Docker container" | src: https://pixi.prefix.dev/latest/workspace/lock_file/ | quote: "resolves the packages - for all environments and platforms listed in the manifest" | type: official
- [C7] pixi.lock 同时锁 conda 与 pypi 包；有 pypi-dependencies 时 conda 的 python 包须带 purls 字段 | src: https://pixi.prefix.dev/latest/workspace/lock_file/ | quote: "for both `conda` and `pypi` packages" | type: official
- [C8] install/run/shell/shell-hook/tree/list/add/remove 会按需生成或更新锁文件；--frozen 只按锁装、--locked 过期即失败、--no-install 只更新锁 | src: https://pixi.prefix.dev/latest/workspace/lock_file/ | quote: "Many Pixi commands will create a lock file if one doesn't already exist, or update it if needed." | type: official
- [C9] 多环境机制：顶层表=default feature，[feature.X] 定义可复用块，[environments] 用 features 列表组合成环境；支持 solve-group 与 no-default-feature | src: https://pixi.prefix.dev/latest/workspace/multi_environment/ | quote: "Environments are defined in the `pixi.toml` under the `[environments]` table." | type: official
- [C10] 同一时刻只能激活一个环境，用 pixi run -e / pixi shell -e 选择；锁文件中包带 environments 字段去重 | src: https://pixi.prefix.dev/latest/workspace/multi_environment/ | quote: "only one environment to be active at any given time" | type: official
- [C11] workspace 级共享依赖：[workspace.dependencies] 可写 path/git 源包，`{ workspace = true }` 继承；相对路径相对根 manifest 解析；需 preview=["pixi-build"]。面向 monorepo 成员包 | src: https://pixi.prefix.dev/latest/build/workspace_dependencies/ | quote: "Relative `path` specs are resolved against the workspace manifest's directory" | type: official
- [C12] Python 解释器本身是 conda 包、装进环境："The Python interpreter is also installed into the environment."；"Pixi automatically manages/bootstraps the Python interpreter for you"；版本可由 pyproject 的 requires-python 决定 | src: https://pixi.prefix.dev/latest/python/tutorial/ | quote: "Pixi automatically manages/bootstraps the Python interpreter for you, so no more `brew`, `apt` or other system install steps." | type: official
- [C13] 跨语言：conda channel 不限 Python | src: https://pixi.prefix.dev/latest/python/tutorial/ | quote: "Channels like `conda-forge` manage packages similar to PyPI but allow for different packages across languages." | type: official
- [C14] pixi build："Pixi can also build packages"；"Pixi backends describe how to build a conda package, for a certain language or build tool"；[package.*] 表需 preview=["pixi-build"] | src: https://pixi.prefix.dev/latest/build/getting_started/ | quote: "The vision is to enable building of packages from source, for any language, on any platform." | type: official
- [C15] 与 PyPI 后端分工：hatchling 构建 python 包，"pixi-build-python turns the Python package into a conda package"；pixi publish 产出 .conda 并可上传 channel | src: https://pixi.prefix.dev/latest/build/getting_started/ | quote: "pixi-build-python` turns the Python package into a conda package" | type: official
- [C16] 后端列表（conda-forge 分发，跨 Linux/macOS/Windows）：pixi-build-cmake、pixi-build-python、pixi-build-rattler-build（"Direct `recipe.yaml` builds with full control"）、pixi-build-ros、pixi-build-r、pixi-build-rust、pixi-build-mojo | src: https://pixi.prefix.dev/latest/build/backends/ | quote: "pixi-build-rattler-build — Direct `recipe.yaml` builds with full control" | type: official
- [C17] 环境默认放 workspace 的 .pixi/envs，每环境一个子目录；激活设 CONDA_PREFIX 并跑激活脚本，仅加 PATH 不够；pixi shell / pixi shell-hook（conda activate 式，eval 用）/ pixi run（自带跨平台 shell、跑 tasks）；环境始终与 pixi.lock 同步 | src: https://pixi.prefix.dev/latest/workspace/environment/ | quote: "All Pixi environments are by default located in the `.pixi/envs` directory of the workspace." | type: official
- [C18] 环境隔离但复用中央缓存硬链 | src: https://pixi.prefix.dev/latest/python/tutorial/ | quote: "Every environment in Pixi is isolated but reuses files that are hard-linked from a central cache directory." | type: official
- [C19] 迁移：`pixi init --import environment.yml`（仅支持 conda-env 格式，落到 default feature）或 `pixi import --format=conda-env environment.yml`（name→feature+环境、pip:→pypi-dependencies、no-default-feature）；反向用 `pixi workspace export conda-environment`（--from-lockfile 钉死版本） | src: https://pixi.prefix.dev/latest/tutorials/import/ | quote: "only the `conda-env` format is supported by `pixi init --import`" | type: official
- [C20] CI：官方 action prefix-dev/setup-pixi（如 @v0.10.0，建议钉版本）；cache: true 以 pixi.lock 哈希为 key；auth-token 等输入；secret 走 GitHub secrets | src: https://pixi.prefix.dev/latest/integration/ci/github_actions/ | quote: "project environment caching is enabled if a `pixi.lock` file is present" | type: official
- [C21] 私有源认证：`pixi auth login`（prefix.dev 走 OAuth 存系统 keychain）；bearer token（Authorization: Bearer 头）、conda-token（嵌进 URL 路径）、basic auth、S3 key；无 keychain 回落 ~/.rattler/credentials.json（RATTLER_AUTH_FILE 可改）；PyPI 侧用 uv 式 python keyring；也支持 .netrc | src: https://pixi.prefix.dev/latest/deployment/authentication/ | quote: "The conda-token is embedded in the URL path." | type: official
- [C22] conda+PyPI 混用：conda-first 三段式（先解 conda→映射 PyPI 名→再解 PyPI）；同名时优先 conda 包 | src: https://pixi.prefix.dev/latest/concepts/conda_pypi/ | quote: "Pixi will install the conda package (and not the PyPI package) if both are available." | type: official
- [C23] PyPI 解析复用 uv 库（非装 uv 工具，同为 Rust 作库用），求解器 PubGrub；conda 求解结果会钉住 PyPI 解（可致冲突，需加 [constraints]） | src: https://pixi.prefix.dev/latest/concepts/conda_pypi/ | quote: "Pixi uses the `uv` library to handle PyPI packages." | type: official
- [C24] conda 包 vs PyPI wheel：conda 全为预编译二进制（"always installs binary packages"），PyPI 为 "Source & Binary (wheel)"；conda 侧质量评价更高 | src: https://pixi.prefix.dev/latest/concepts/conda_pypi/ | quote: "it always installs binary packages, meaning that it doesn't need to compile anything" | type: official
- [C25] 关系定性：conda="The original package manager, written in Python"；mamba="A faster drop-in replacement for conda, with a C++ solver"；pixi="A modern, Rust-based package manager with lock files, tasks, and multi-environment support" 且 "Not a drop-in replacement — it rethinks the workflow" | src: https://pixi.prefix.dev/latest/conda_ecosystem/ | quote: "Not a drop-in replacement — it rethinks the workflow." | type: official
- [C26] pixi 由 Rattler 驱动："a set of Rust libraries that implement the conda ecosystem from scratch"；conda 生态语言无关、包全为预编译、channel=HTTP 包仓库；conda-forge 为社区默认 channel，30,000+ 包 | src: https://pixi.prefix.dev/latest/conda_ecosystem/ | quote: "Pixi is powered by **Rattler**, a set of Rust libraries that implement the conda ecosystem from scratch" | type: official

## leads
- pixi global（全局工具管理，pipx 式）与 detached environments 可作环境管理对比的补充。
- rattler 作为引擎被其它工具复用（"Rattler is not a CLI tool"），是 conda 生态 Rust 化的关键。
- conda recipe（recipe.yaml/rattler-build）写法不在本轮范围，见 build/tutorials。
