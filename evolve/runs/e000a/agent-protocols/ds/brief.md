# Brief — agent 协议全景

## 任务
帮用户理清「agent 时代」各种「协议」分别管什么、有什么不同，产出一份 taxonomy + 对照文档。

## 读者
了解 LLM/agent 生态、在网上零散看到 MCP/A2A/ACP/AG-UI 等词但没有系统认知的开发者。要在 5 分钟内建立「谁管什么层、彼此什么关系」的心智模型，再按需查字段级细节（传输、鉴权、版本）。

## 范围内
- 四个种子协议讲清楚：MCP、A2A、ACP（IBM）、ACP（Zed）、AG-UI（用户给了 4 个关键词但点名 ACP 有两个，等于 5 个实体）。
- 大厂支持面：OpenAI、Anthropic、Google、Microsoft 各自支持哪些协议、有没有自家变体/竞品。
- 横切维度：鉴权、版本/治理、成熟度、如何选型。
- 调研中发现的、确属这个 scope（agent 互操作/上下文协议）的其他协议或命名冲突，视重要性收进「其他值得知道」，不铺开细讲。

## 范围外
- 具体 SDK 代码教程、逐字段 API 参考搬运。
- 与 agent 互操作无直接关系的通用协议（HTTP/GraphQL 本身、纯函数调用历史）只作背景一句带过。
- 支付类协议（如 AP2）等如果只是 leads 里提到、非用户点名，最多一行带过。

## 用户点名的疑点（成稿必须给结论）
1. IBM 的 Agent Communication Protocol 和 Zed 的 Agent Client Protocol 是不是一回事？—— 需给出：不是一回事 + 两者现状（尤其 IBM ACP 是否仍独立存在/是否并入别处）。
2. MCP 的 SSE 传输是否已经废弃？—— 需给出：官方原句 + 具体版本号 + 现在推荐用什么替代。

## 完成标准
- taxonomy：按「管的是哪一层交互」分家族，能解释矩阵里大部分差异。
- 对照矩阵：每个实体在每个维度上有可追溯到一手来源的取值，或明确标 ❓/∅。
- 厂商支持矩阵：4 厂商 × 5 协议（含变体名）。
- 两个用户疑点有明确结论段落。
- 成稿 ≤ 9000 字符（含来源节），终审后仍需满足。
