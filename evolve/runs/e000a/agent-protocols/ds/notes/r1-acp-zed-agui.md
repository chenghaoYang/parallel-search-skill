## claims — Zed ACP
- [C1] Zed ACP 定位：代码编辑器（客户端）与 AI 编程代理之间的交互。| src: https://agentclientprotocol.com | quote: "a protocol that standardizes communication between code editors" | type: official
- [C2] Zed ACP 核心抽象：session（会话）、prompt turn（对话轮次）、message types（消息类型）、content blocks、tool calls | src: https://agentclientprotocol.com/llms.txt | quote: "Sessions that maintain conversation state, Prompt turns representing the core conversation flow, Message types for structured communication, Tool calls enabling agents to execute actions" | type: official
- [C3] Zed ACP 传输（本地）：JSON-RPC 2.0 over stdio（代理作为编辑器子进程运行）。| src: https://agentclientprotocol.com | quote: "Local agents: Run as editor sub-processes using JSON-RPC over stdio" | type: official
- [C4] Zed ACP 传输（远程）：HTTP/WebSocket 用于云托管或独立基础设施，目前在研发中。| src: https://agentclientprotocol.com | quote: "Remote agents: Cloud-hosted or separate infrastructure via HTTP/WebSocket (currently in progress)" | type: official
- [C5] Zed ACP 状态归属：客户端（Zed 编辑器）拥有 Agent Panel 和 Threads Sidebar 中的会话线程；代理通常拥有自己的运行时、认证、模型选择、工具。| src: https://rywalker.com/research/zed-agent-client-protocol | quote: "Zed hosts the thread in the Agent Panel and Threads Sidebar, while the External Agent usually owns its own runtime, auth, model selection, tools, and native configuration" | type: secondary
- [C6] Zed ACP 鉴权：协议支持初始化 → 可选鉴权 → 会话创建/恢复 → prompt turns 生命周期；鉴权由各代理实现者负责。| src: https://rywalker.com/research/zed-agent-client-protocol | quote: "The lifecycle runs initialization → optional authentication → session creation/resumption → prompt turns" | type: secondary
- [C7] Zed ACP 协议版本：wire protocol v1 为当前稳定版本；schema artifacts 按版本发布（schema/v1, schema/v2 等）。| src: https://github.com/zed-industries/agent-client-protocol | quote: "the current stable wire protocol version is 1, Wire compatibility is determined by the protocolVersion exchanged during initialization" | type: official
- [C8] Zed ACP 版本历史：预 1.0 状态，v0.13.6（2026 年 6 月 5 日发布），仍在快速迭代中预期有破坏性变更。| src: https://rywalker.com/research/zed-agent-client-protocol | quote: "at v0.13.x the protocol is still iterating rapidly; implementers should expect breaking changes until a stable release lands" | type: secondary
- [C9] Zed ACP 治理：由 Zed Industries 主导，JetBrains 在注册表一侧参与投资，不属于中立基金会模式。| src: https://rywalker.com/research/zed-agent-client-protocol | quote: "the spec is driven by Zed (with JetBrains on the registry), not a foundation; there is no Linux Foundation-style neutral home" | type: secondary
- [C10] Zed ACP 与 LSP 设计启发：官方文档明确提及"ACP draws inspiration from the Language Server Protocol"。| src: https://agentclientprotocol.com | quote: "ACP draws inspiration from the Language Server Protocol by enabling editors and agents to communicate through a common interface" | type: official
- [C11] Zed ACP 社区支持：官方 SDK 包括 Rust、Python、Java、Kotlin、TypeScript；使用 Apache License 2.0；接受无 CLA 的贡献。| src: https://github.com/zed-industries/agent-client-protocol | quote: "Official SDKs exist for: Kotlin, Java, Python, Rust, TypeScript; accepts contributions without requiring a Contributor License Agreement, with contributions licensed under Apache License 2.0" | type: official
- [C12] Zed ACP 厂商采用：编辑器支持包括 Zed、JetBrains IDE、VS Code、Neovim、Emacs 等；代理包括 Claude Agent、Codex CLI、GitHub Copilot、OpenHands 等 50+ 整合。| src: https://zed.dev/acp | quote: "Editors: Zed, JetBrains IDEs, VS Code, Neovim, Emacs, and others; Agents: Claude Agent, Codex CLI, GitHub Copilot, OpenHands, and 50+ additional integrations" | type: official
- [C13] Zed ACP 与 MCP 关系：官方文档提到"reuses JSON representations from the Message Context Protocol (MCP) where applicable"。| src: https://agentclientprotocol.com | quote: "The protocol reuses JSON representations from MCP where applicable but includes custom types for coding-specific UX features, like diff visualization" | type: official
- [C14] IBM ACP vs Zed ACP 完全不同：IBM 的 Agent Communication Protocol 是 agent↔agent 协议（由 IBM Research/BeeAI 主导），而 Zed 的 Agent Client Protocol 是 editor↔agent 协议；不是同一回事。| src: https://4sysops.com/archives/comparing-ai-protocols-mcp-a2a-agp-agntcy-ibm-acp-zed-acp/ | quote: "IBM's Agent Communication Protocol (ACP) is an agent-to-agent interoperability protocol; Zed's Agent Client Protocol (ACP) standardizes communication between code editors/IDEs and coding agents" | type: secondary

## claims — AG-UI
- [C15] AG-UI 定位：AI 代理后端与用户面向应用前端之间的交互（agent ↔ user interaction layer）。| src: https://docs.ag-ui.com/introduction | quote: "AG-UI occupies the Agent ↔ User Interaction layer within agentic architecture" | type: official
- [C16] AG-UI 核心抽象：17 个标准事件类型组织在 5 个类别中：Lifecycle Events（RunStarted, RunFinished, RunError, StepStarted, StepFinished）、Text Message Events（TextMessageStart, TextMessageContent, TextMessageEnd）、Tool Call Events（ToolCallStart, ToolCallArgs, ToolCallEnd, ToolCallResult）、State Management Events（StateSnapshot, StateDelta, MessagesSnapshot）、Special Events（RawEvent, CustomEvent）。| src: https://www.copilotkit.ai/blog/master-the-17-ag-ui-event-types-for-building-agents-the-right-way | quote: "AG-UI defines 17 core event types (special cases included), organized into five categories: Lifecycle Events (5), Text Message Events (3), Tool Call Events (4), State Management Events (3), Special Events (2)" | type: secondary
- [C17] AG-UI 传输：支持灵活的中间件层任意事件传输（SSE、WebSockets、webhooks），默认包含 HTTP 实现。| src: https://github.com/ag-ui-protocol/ag-ui | quote: "Flexible middleware layer supporting any event transport (SSE, WebSockets, webhooks), Reference HTTP implementation with default connector included" | type: secondary
- [C18] AG-UI 状态归属：后端拥有会话/状态（使用 threadId 和 runId），前端负责显示和交互；每个请求在未传递完整历史的情况下是无状态的。| src: https://docs.ag-ui.com/introduction | quote: "AG-UI has threadId and runId fields, but maintaining conversation history across messages is your responsibility. Each request is stateless unless you pass the full history" | type: official
- [C19] AG-UI 鉴权：由后端负责，支持 FastAPI 依赖注入集成 OAuth 2.0、JWT、Azure AD/Entra ID、速率限制等。| src: https://docs.ag-ui.com/introduction | quote: "Who the user is, what tenant they're in, and what they're allowed to do come from authenticated server state. The dependencies parameter accepts any FastAPI dependency, enabling integration with OAuth 2.0, JWT, Azure AD / Entra ID, rate limiting" | type: official
- [C20] AG-UI 版本历史：v1.0.0 于 2026-09-17 发布，作为 GA 版本；之前采用月度发布节奏（2026-08-27、2026-09-08、2026-09-10、2026-09-14）。| src: https://github.com/ag-ui-protocol/ag-ui/releases | quote: "Release Release 2026-09-17 with protocol version 1.0.0" | type: official
- [C21] AG-UI 治理：由 CopilotKit 主导（venture-backed startup），官方没有中立基金会家园（不同于 A2A 的 Linux Foundation、MCP 的开放治理），MIT 许可证。| src: https://github.com/ag-ui-protocol/ag-ui/discussions/166 | quote: "AG-UI was born from CopilotKit's initial partnership with LangChain and CrewAI; the spec is stewarded by a venture-backed startup" | type: secondary
- [C22] AG-UI 与 CopilotKit 关系：AG-UI 原始于 CopilotKit 内部解决方案，已发展为开源运动并被多个 agent 框架采用和扩展。| src: https://github.com/ag-ui-protocol/ag-ui/discussions/166 | quote: "What started as an internal solution inside the CopilotKit ecosystem, has grown into an open-source movement" | type: secondary
- [C23] AG-UI 厂商采用：框架集成包括 LangChain、CrewAI、Microsoft Agent Framework、Google ADK、AWS（Strands、Bedrock AgentCore）、Pydantic AI、LlamaIndex；多语言 SDK（Python、JavaScript、Kotlin、Go、Rust、.NET 等）。| src: https://docs.ag-ui.com/introduction | quote: "AG-UI integrates with LangChain, CrewAI, Microsoft Agent Framework, Google ADK, AWS services, Mastra, Pydantic AI, LlamaIndex, and numerous community implementations across Python, JavaScript, Kotlin, Go, Rust, .NET, and other languages" | type: official
- [C24] AG-UI 与其他协议关系：官方文档明确定位 AG-UI、MCP、A2A 为互补协议——MCP 为代理提供工具，A2A 用于 agent-to-agent 协调，AG-UI 将代理带入用户面向应用。| src: https://docs.ag-ui.com/introduction | quote: "AG-UI complements other agentic protocols: MCP provides tools to agents, A2A enables agent-to-agent communication, while AG-UI specifically brings agents into user-facing applications" | type: official
- [C25] AG-UI 成熟度：v1.0 GA（2026-09-17 发布），生产可用，已在 Microsoft/Google/AWS 实现中采用。| src: https://github.com/ag-ui-protocol/ag-ui/releases | quote: "AG-UI protocol 1.0.0 released as production version with implementations in Microsoft Agent Framework, Google ADK, AWS Bedrock AgentCore" | type: official

## conflicts
- 无明显冲突。Zed ACP 和 AG-UI 职责层不同（editor↔agent vs backend↔UI），治理模式差异正常反映不同的生态位置。

## gaps
- Zed ACP: 官方文档未明确说明与 IBM ACP 的命名冲突关系或澄清声明（须依赖二手来源如 4sysops 的对比）
- AG-UI: 官方文档未详细说明前端/后端对工具执行结果的拒绝/修正流程（TOOL_CALL_RESULT 处理后是否有反驳机制）

## leads
- Zed ACP 可能 1.0 发布在即（当前 v0.13.6 June 2026，距今已三月多）—— 应监控后续 stable release 公告
- AG-UI v1.0 刚发布（2026-09-17，距今一周），市场采用速度可观（9000+ GitHub stars），但 venture-backed 治理模式可能引发长期中立性疑虑
- 三个互补协议（MCP/A2A/AG-UI）的分工已逐渐稳定：MCP 处理工具层、A2A 处理 agent 协调、AG-UI 处理前端呈现，但交界面（如 AG-UI 中的工具调用是否复用 MCP schema）仍需官方澄清
