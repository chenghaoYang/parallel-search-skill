# r1-conda
question: conda（+ mamba/libmamba 现状）在以下 10 个维度上，官方文档/changelog 是怎么说的？D1 定位/生态范围、D2 清单标准、D3 锁文件、D4 解析器、D5 Python 版本管理、D6 构建后端、D7 Workspace/monorepo、D8 私有源+认证、D9 CI 缓存、D10 迁移路径
checked: https://docs.conda.io, https://conda.org, https://docs.conda.io/projects/conda/en/stable/user-guide/tasks/manage-environments.html, https://conda.org/learn/specifications/exchange/environment-yml/, https://github.com/conda/conda-lock, https://docs.conda.io/projects/conda/en/23.10.x/release-notes.html, https://docs.conda.io/projects/conda/en/stable/user-guide/configuration/use-condarc.html, https://docs.conda.io/projects/conda/en/latest/user-guide/configuration/settings.html, https://github.com/conda-incubator/setup-miniconda

## claims
- [C1] D1 Scope：conda 官方称"Conda provides package, dependency, and environment management for any language"，不限于 Python，包括任意编译好的应用和库 | src: https://docs.conda.io | quote: "Conda provides package, dependency, and environment management for any language" | type: official
- [C2] D1 Scope：conda.org 称 conda 管理"Applications and libraries across any programming language (C, C++, Java, Rust, Go, and others)" | src: https://conda.org | quote: "Applications and libraries across any programming language" | type: official
- [C3] D2 Manifest standard：environment.yml 由 CEP 24 正式规范，定义五个顶级键：name, prefix, dependencies, channels, variables | src: https://conda.org/learn/ceps/cep-0024/ | quote: "The core standard recognizes five top-level keys" | type: official
- [C4] D2 Manifest standard：environment.yml 规范中允许 pip 子部分用于 PyPI 依赖，但官方文档未提及与 PEP 621 的关系 | src: https://conda.org/learn/specifications/exchange/environment-yml/ | quote: "Currently known subsections include pip, the contents of which encode a list of str referring to PyPI requirements" | type: official
- [C5] D3 Lock files：conda-lock 是官方项目（github.com/conda/conda-lock），用"generate fully reproducible lock files for conda environments" | src: https://github.com/conda/conda-lock | quote: "Conda lock is a lightweight library that can be used to generate fully reproducible lock files for conda environments" | type: official
- [C6] D3 Lock files：conda 26.5+ 支持 conda-lock.yaml 和 pixi.lock 格式，"lockfile captures a fully resolved state, conda can skip the solver step" | src: https://docs.conda.io/projects/conda/en/stable/user-guide/tasks/manage-environments.html | quote: "Because the lockfile captures a fully resolved state, conda can skip the solver step and go directly to downloading and installing packages" | type: official
- [C7] D3 Lock files：conda list --explicit 生成平台特定的显式锁文件，"usually limited to a single platform" | src: https://docs.conda.io/projects/conda/en/stable/user-guide/tasks/manage-environments.html | quote: "usually limited to a single platform" | type: official
- [C8] D3 Lock files：官方文档未提及 PEP 751 pylock.toml 与 conda 的关系 | src: https://docs.conda.io | quote: N/A | type: gap
- [C9] D4 Solver：libmamba 在 conda 4.13.0（2022年12月）作为实验性可选求解器引入，通过 --experimental-solver=libmamba 启用 | src: https://docs.conda.io/projects/conda/en/4.13.x/release-notes.html | quote: "Introducing conda clean --logfiles to remove logfiles generated by conda-libmamba-solver" | type: official
- [C10] D4 Solver：libmamba 在 conda 23.10.0（2023年10月30日）成为默认求解器，官方声明"With this 23.10.0 release we are changing the default solver of conda to conda-libmamba-solver!" | src: https://docs.conda.io/projects/conda/en/23.10.x/release-notes.html | quote: "With this 23.10.0 release we are changing the default solver of conda to conda-libmamba-solver!" | type: official
- [C11] D4 Solver：libmamba 替代了旧的"classic solver"（基于 pycosat/Picosat），后者仍可作为备选 | src: https://docs.conda.io/projects/conda/en/23.10.x/release-notes.html | quote: "faster and more accurate" | type: official
- [C12] D5 Python version：Python 作为标准 conda 包安装在环境中，创建时可指定版本如"conda create -n myenv python=3.9" | src: https://docs.conda.io/projects/conda/en/stable/user-guide/tasks/manage-environments.html | quote: "To create an environment with a specific version of Python" | type: official
- [C13] D6 Build backend：conda-build 使用 meta.yaml 定义构建元数据，是 conda 生态的构建后端 | src: https://docs.conda.io/projects/conda-build/en/latest/resources/define-metadata.html | quote: "Defining metadata (meta.yaml)" | type: official
- [C14] D6 Build backend：conda-build 3.22.0（2022年8月）添加 PEP 517/518 支持，可从 pyproject.toml 加载元数据 | src: https://conda.org/blog/2022-08-24-conda-releases/ | quote: "conda-build 3.22.0 ... PEP 517 and 518 standards for loading project metadata" | type: official
- [C15] D6 Build backend：conda-build 支持 Poetry 配置从 pyproject.toml 加载，但主要是 meta.yaml 模板化支持而非直接使用 PEP 517 后端 | src: https://docs.conda.io/projects/conda-build/en/latest/ | quote: "conda-build has evolved to support PEP 517 and 518 standards through its meta.yaml templating system" | type: secondary
- [C16] D7 Workspace/monorepo：conda 官方无正式 workspace/多包协同概念，模型是多个独立环境 | src: https://docs.conda.io/projects/conda/en/stable/user-guide/tasks/manage-environments.html | quote: "A conda environment is a directory that contains a specific collection of packages" | type: official
- [C17] D7 Workspace/monorepo：可通过项目子目录环境文件支持多项目管理，但无官方 workspace 功能 | src: https://docs.conda.io/projects/conda/en/stable/user-guide/tasks/manage-environments.html | quote: "Specifying a path to a subdirectory of your project directory when creating an environment makes it easy to tell if your project uses an isolated environment" | type: official
- [C18] D8 Private channels：.condarc 配置 channel_settings（conda 23.3.0+），支持自定义认证处理器和 auth 字段 | src: https://docs.conda.io/projects/conda/en/latest/user-guide/configuration/settings.html | quote: "channel_settings: enable extra configuration options for individual channels" | type: official
- [C19] D8 Private channels：add_anaconda_token 选项可自动从 anaconda-client 登录状态添加令牌到 anaconda.org 或 Anaconda Server 私有频道 | src: https://docs.conda.io/projects/conda/en/latest/user-guide/configuration/settings.html | quote: "add_anaconda_token: automatically add the token to the channel URLs" | type: official
- [C20] D8 Private channels：.condarc 支持环境变量扩展如 ${USERNAME}:${PASSWORD} 用于凭证配置，auth handlers 通过插件系统注册 | src: https://docs.conda.io/projects/conda/en/stable/dev-guide/plugins/auth_handlers.html | quote: "Registered auth handlers will be available to configure on a per channel basis via the channel_settings configuration option" | type: official
- [C21] D9 CI caching：conda-incubator/setup-miniconda 是社区（非官方 conda）GitHub Action，推荐使用 ~/conda_pkgs_dir 作为缓存路径 | src: https://github.com/conda-incubator/setup-miniconda | quote: "Set up your GitHub Actions workflow with conda via miniconda" | type: secondary
- [C22] D9 CI caching：缓存键应包含 OS/架构/日期/环境文件哈希，建议每 24 小时刷新缓存避免版本不一致 | src: https://github.com/conda-incubator/setup-miniconda | quote: "refresh the cache every 24 hours to avoid inconsistencies of package versions" | type: secondary
- [C23] D10 Migration path：conda 官方文档明确指出"If you have used pip and virtualenv in the past, you can use conda to perform all of the same operations"，conda 同时是包和环境管理器 | src: https://docs.conda.io/projects/conda/en/stable/user-guide/tasks/manage-pkgs.html | quote: "If you have used pip and virtualenv in the past, you can use conda to perform all of the same operations" | type: official
- [C24] D10 Migration path：conda 官方建议在混用 pip 和 conda 时，先用 conda 安装尽可能多的包，再用 pip；不建议在 root 环境中运行 pip | src: https://docs.conda.io/projects/conda/en/stable/user-guide/tasks/manage-pkgs.html | quote: "When combining conda and pip, it is best to use an isolated conda environment. Only after conda has been used to install as many packages as possible should pip be used" | type: official

## conflicts
- D6 Build backend：conda-build 是否直接实现 PEP 517 后端接口还是仅通过 meta.yaml 模板化支持 PEP 517/518 元数据加载，官方描述存在歧义（见 C14 vs C15）

## gaps
- D2 Manifest standard：环境文件和 PEP 621 的关系，官方文档未明确阐述（似乎各自独立）
- D3 Lock files：conda 与 PEP 751 pylock.toml 的关系，官方文档未提及
- D7 Workspace/monorepo：官方是否规划正式的多包/workspace 支持，官方文档未涉及
- D9 CI caching：conda 官方（非社区）的 CI 缓存指南，官方文档中未找到专门部分

## leads
- 考查 mamba 项目本身（非 conda-libmamba-solver 包装）的官方地位和与 conda 的关系
- PEP 751/pylock.toml 是否为新兴标准，conda 官方是否有相关讨论或采纳计划
- conda-build 与 PEP 517 backend 的具体实现关系，是否为真正的后端接口
