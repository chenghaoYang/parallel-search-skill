## conflicts
- No official conflicts found. D2 absence confirmed via closed duplicate issue. D5 algorithm specifics and D8 migration guide genuinely absent from official sources (gaps, not conflicts).

## gaps
- **D5 resolver algorithm**: CHANGELOG and docs mention "dependency resolution" and "solver" but do NOT state which algorithm is implemented (e.g., PubGrub, constraint-satisfaction, custom). Searched CHANGELOG for "pubgrub", "mixology", "algorithm", "constraint" - none found. Third-party sources (DeepWiki, Medium) mention PubGrub but cannot be sourced to official Poetry docs/code.
- **D5 resolver speed improvements**: CHANGELOG documents some performance fixes (backtracking optimization #7950, PEP 658 metadata without wheels #5509, lazy-wheel config #8815) but no comprehensive "solver performance" documentation page exists in python-poetry.org.
- **D8 migration guide**: No dedicated "Migrating from setup.py/requirements.txt to Poetry" page in official docs. `poetry init` does not support auto-import of existing dependency declarations (unlike PDM's auto-detection).

## leads
- If seeking definitive resolver algorithm name, check python-poetry/poetry-core source code directly for imports/naming; CHANGELOG + docs do not expose this.
- Path dependencies documented as Poetry's "monorepo solution", but users repeatedly request batch-operation workspace feature (Issues #936, #7677); suggest D2 answer clarify: "Poetry supports path dependencies for local multi-package development but does not provide workspace/batch-operation feature matching Cargo or npm workspaces."
