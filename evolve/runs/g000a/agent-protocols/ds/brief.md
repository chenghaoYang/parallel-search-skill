# 任务简报

读者：要在产品里接「agent 协议」的工程师，以及被缩写淹没的技术决策者。不是实现者手册。

截至调研日 2026-09-24。成稿要让读者在几分钟内建立下面的认知，再按表格查原名：

1. MCP、A2A、两种 ACP、AG-UI 各自守哪一条边，什么情况下叠放、什么情况下才互相替代。
2. 网上说的两个 ACP（IBM 的 Agent Communication Protocol，Zed 的 Agent Client Protocol）是不是同一个协议。必须给出结论。
3. MCP 的 SSE 传输是否已经废弃。必须给出结论：哪一版规范、被什么替代、旧传输还写不写在规范里。
4. OpenAI、Anthropic、Google、微软各自官方支持哪些协议、有没有自家变体（只收官方页面能证明的）。
5. 鉴权、版本、治理怎么落到「该选哪个」。

## 范围内

- 四个种子及其同名歧义：MCP（Model Context Protocol）、A2A（Agent2Agent）、ACP-IBM、ACP-Zed、AG-UI。
- 上述四家的官方支持范围与自家变体。
- 鉴权、版本与弃用、治理主体、选型。
- 仍属于「agent 互操作协议」的近邻：只在能划清边界时写入，不展开成第二篇综述。

## 范围外

- SDK 安装、代码教程、框架内部编排（除非厂商把它称为跨厂商协议或某协议的变体）。
- 一般性的 function calling / tool use API。只有当官方把它当作某协议的替代或变体时才收。
- 支付、身份、浏览器自动化等相邻协议。scout 可以记线索；未证明能划清边界的不进正文。

## 点名疑点（成稿必须有结论，哪怕结论是「官方没写」）

- Q-acp：IBM ACP 与 Zed ACP 是不是一回事。
- Q-sse：MCP 的 SSE 传输是否废弃。

## 完成标准

- taxonomy 的分类轴能解释矩阵里的主要差异。
- 点名疑点有明确结论，并出现在「一屏看懂」。
- 正文每个具体事实能追到笔记里的一条主张；没有来源的只写「未决」。
- `ds/report.md` 字符数（Python `len()`）≤ 9000，含来源节。每轮重写，不许越改越长。
- 扩展轮数上限 3（R1 铺开，R2 起只打缺口）。最后一轮之后做终审，终审后再收束一次。
