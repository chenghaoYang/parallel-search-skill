## conflicts
- 依赖组位置，两边都是文档版本选择器 2.5，不裁决。dependency-specification：quote: "Only main dependencies can be specified in the `project` section. Other Dependency groups must still be specified in the `tool.poetry` section." src: https://python-poetry.org/docs/dependency-specification/ 。managing-dependencies：quote: "To declare a new dependency group, use a `dependency-groups` section according to PEP 735 or a `tool.poetry.group.<group>` section where `<group>` is the name of your dependency group (for instance, `test`):" src: https://python-poetry.org/docs/managing-dependencies/
- 是否安装解释器，两边都是文档 2.5，不裁决。basic-usage Setting a Python Version：quote: "Poetry will not install a Python interpreter for you." src: https://python-poetry.org/docs/basic-usage/ 。CLI python install：quote: "The `python install` command installs the specified Python version from the Python Standalone Builds project." src: https://python-poetry.org/docs/cli/
- FAQ 拼写：正文是 tools.poetry，同页 TOML 示例表头是 [tool.poetry]。quote: "How do I migrate an existing Poetry project using `tools.poetry` section to use the new `project` section (PEP 621)?" 以及 quote: "The `requires-poetry` is added to the `tools.poetry` section." src: https://python-poetry.org/docs/faq/

## gaps
- https://python-poetry.org/docs/managing-environments/ （版本选择器 2.5）已打开并查找 install Python / will not install：没有 “will not install” 或 “install a Python interpreter”。该页只写用安装 Poetry 时的 Python 建环境，不兼容就去找已有解释器，找不到则提示显式 activate；示例是用户自己 pyenv install。
- C18 的 quote 只有版本号 “Introduced in 2.1.0”；“python install 会安装解释器”的原句在 conflicts 第二条，未再占一条 claim。

## leads
- 2.3 公告（2026-01-18）写 Poetry 2.2.0 引入 PEP 735，并用 PEP 735 组时建议 requires-poetry 到 2.3.0+（lock hash），见 https://python-poetry.org/blog/announcing-poetry-2.3.0/
