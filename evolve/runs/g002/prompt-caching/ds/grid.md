# Taxonomy grid v1

状态：`✅` 一手+原句；`⚠` 仅二手；`⚔` 来源冲突；`❓` 缺口；`∅` 官方未写（已定向查过）；`—` 不适用。

v0→v1：主轴从「自动 / 显式断点 / 命名资源 / 网关」改成三档控制点，并单列计费结构和介质。原因：同为默认开启的 OpenAI、DeepSeek、Gemini implicit，写价和是否承诺折扣并不相同；Anthropic 自 2026-02-19 起可以只在顶层放 `cache_control`，不再等于「每个块手打断点」。新增 D10，组织 / 机器 / `user_id` / 并行可见性装不进「内容一改就失效」。通义拆成隐式、显式两行（官方写两种模式互斥）；格子仍待 R2 工人填，不把 scout 定位句算成已填。

## 分类轴

轴 A · 控制点：默认就会缓存／请求里必须出现缓存字段／先创建命名资源／网关自己不定义、透传上游。

轴 B · 钱：写溢价+读折扣／只分命中与未命中单价／读折扣+按 TTL 收存储／可能打折但不承诺。

轴 C · 介质：单机内存 KV／明确不落盘／硬盘前缀／可命名对象。

## 维度

| ID | 维度 | 这一列回答什么 |
|---|---|---|
| D1 | 触发 | 不改请求会不会缓存？默认前缀、请求内开关，还是先创建资源 |
| D2 | 缓存单位 | 键是整段前缀、断点之前的内容，还是命名 cache 对象 |
| D3 | 门槛 | 最少 token、断点个数、从哪一段才可能命中 |
| D4 | 命中信号 | 响应里哪个字段表示命中、未命中 |
| D5 | 读价 | 命中 token 相对普通 input 怎么计价 |
| D6 | 写价与存储 | 写入或保留是否另收费 |
| D7 | TTL | 默认活多久、能否指定、过期后怎样 |
| D8 | 失效 | 哪些内容或参数改动导致不命中 |
| D9 | 模型与端点 | 哪些模型、哪条 API |
| D10 | 隔离与并发 | 按组织、workspace、机器还是终端用户隔离；并行请求何时看得见 |
