# 简报

读者：准备开新 Python 项目，或从 pip / Poetry / conda 迁过来的开发者。不是打包规范的作者。

几分钟内要建立的认知：

- 这几个工具分属哪几个家族，家族差在哪。
- 新项目默认该怎么选（按项目是否要 conda 包、要不要单仓库多包、要不要工具自己装 CPython）。
- 两个传闻的结论：PEP 751 `pylock.toml`，uv 和 pip 各自是「能生成 / 能安装 / 默认锁文件」里的哪一种；Poetry 2 的新项目是否改用 PEP 621 `[project]`，旧的 `[tool.poetry]` 还能否用。

然后能按表查清：锁文件、workspace、Python 版本、构建后端、迁移命令、CI 缓存、私有源。

## 范围

范围内：

- 种子：uv、pip、Poetry、PDM、pixi / conda。
- 维度：清单格式、锁文件（含 PEP 751）、workspace/monorepo、CPython 版本管理、构建后端、依赖组与包宇宙、从旧工具迁入、CI 缓存、私有源。
- 选型必须知道的坑（迁移、混用 conda 与 pip、锁文件没提交、凭证进锁等），以官方文档为准。
- scout 若证明某个近邻工具会改变选型（pip-tools、Hatch、Rye、mamba、conda-lock），可以升格进网格，但成稿里不能变成第六份工具手册。

范围外：

- 命令大全、每个子命令的旗标列表。
- 国内镜像站的运营现状（官方配置键可以写，镜像站评测不写）。
- 速度跑分，除非官方文档给出影响选型的机制（例如锁是跨平台一份还是按平台拆开）。
- 与 Python 包管理无关的 conda 包（R、CUDA 安装细节），只在「新项目要不要离开 PyPI」时出现。

## 用户点名的疑点（成稿必须给结论）

1. PEP 751 `pylock.toml`：uv 和 pip 是否都已支持？必须拆开「生成 / 用它安装 / 默认锁是不是它」，并写出版本或文档日期。
2. Poetry 2 是否改用标准 `[project]` 表？必须拆开「新项目模板默认写什么」「只有 `[tool.poetry]` 的旧项目还能不能读」「两表同时存在以谁为准」。

## 完成标准

- 上述两个疑点在「一屏看懂」里有明确结论；边界主张（不支持、自某版起、默认、唯一）过反证后才写进那一节。
- 五个种子在网格上为 ✅、∅、⚔ 或 ⚠，不留无说明的 ❓。
- taxonomy 能解释锁文件、谁装 Python、私有源这三列的大部分差异。
- `ds/report.md` 的 `len()` ≤ 9000，且最终同时写到 `./report.md`。
- 正文每个具体事实能追到笔记里的一条主张。
