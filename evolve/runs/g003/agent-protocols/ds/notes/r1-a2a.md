## conflicts
- 治理主体措辞不一致，未裁决。官网与 GOVERNANCE.md 只写捐赠给 Linux Foundation、由 TSC 技术监督，正文不提 AAIF。A2A 博客写 “Growth Stage project at the Agentic AI Foundation” 与 “Linux Foundation-directed AAIF”。AAIF 写 hosted project。2025-06-23 LF：“Under the Linux Foundation’s governance”。2026-09-14 LF：“founding projects including MCP, A2A” 且 “AAIF governs the core standards and protocols”。
- ACP：AAIF 写 IBM Agent Communication Protocol merged into A2A。规范 Appendix B 只有与 MCP 互补的句子，没有 ACP 原句。官网与 v1 公告也只谈 MCP。
- Key Concepts：“JSON-RPC 2.0 is used as the payload format for all requests and responses.” 规范则是 JSON-RPC、gRPC、HTTP/REST。enterprise-ready：“TLS 1.2 or higher is recommended”；规范 7.1：“TLS 1.3+ recommended”。
- 规范 3.1.11 写 `AgentCard.security` 与 `securitySchemes`；字段表是 `securityRequirements`。路径：1.4 为 `spec/a2a.proto`，5.7 为 `specification/a2a.proto`。what-is-a2a 图为 `POST /sendMessage` 与 `/.well-known/agent-card`；规范为 `SendMessage`、`POST /message:send`、`/.well-known/agent-card.json`。

## gaps
- 规范全文检索 acp / Agent Communication Protocol / ibm 为 0，但无“未提及 ACP”原句，故不写成否定 claim。2026-09-24 的 https://a2a-protocol.org/dev/ 与 latest 首页相同，未见 “IBM ACP: Incorporated into the A2A Protocol”，不采信。未用 i-am-bee/acp。v1 博客正文无日期；三月仅来自 AAIF 原句与 URL。未核对 GitHub release tag。

## leads
- 已打开的 A2A 页未区分 Agent Client Protocol、Agentic Commerce Protocol 与 IBM ACP。
- key-concepts 与 what-is-a2a 的传输/端点相对规范 1.0 可能滞后。
