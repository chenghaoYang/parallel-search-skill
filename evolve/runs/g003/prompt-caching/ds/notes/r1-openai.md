# r1-openai
question: 截至 2026-09-24，OpenAI 官方 API 的 prompt caching 现在怎么触发、怎么计费、能活多久、响应里怎么看见命中、什么改动会失效？

## conflicts
- 查找窗口：指南写 explicit-only 为 “The first 2 and latest 50 explicit breakpoints.”（https://developers.openai.com/api/docs/guides/prompt-caching）；Responses 与 Chat create 都写 “For cache matching, OpenAI considers up to the latest 80 breakpoints in the conversation, without a content-block lookback limit.”（https://developers.openai.com/api/reference/resources/responses/methods/create 与 https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create）。
- 寿命上限：指南 “though OpenAI may retain it longer” 且表内 GPT-5.6 寿命为 “At least 30 minutes after the latest write or reuse”，未写 24h 封顶。your-data 写 “not retained after the 24-hour expiration”，并写 ttl “controls the minimum cache lifetime, not this maximum application-state retention period.”（https://developers.openai.com/api/docs/guides/your-data）。
- `prompt_cache_retention`：API reference 标 “Deprecated. Use `prompt_cache_options.ttl` instead.”，又写 “For `gpt-5.5`, `gpt-5.5-pro`, and future models, only `24h` is supported.”，同时 `prompt_cache_options` “Supported for `gpt-5.6` and later”。指南仍规定更早模型用 `prompt_cache_retention`，GPT-5.6+ 的 ttl 只支持 `30m`，迁移句是 “Replace `prompt_cache_retention` with `prompt_cache_options.ttl`.”。
