## conflicts
- Gemini 同页并存两套：implicit「Implicit caching works seamlessly — no manual setup or additional cache_control breakpoints required」且「No cache write or storage costs」，TTL「on average 3-5 minutes, but will vary」；后文「Gemini caching in OpenRouter requires you to insert cache_control breakpoints」且「Cache Writes have a 5 minute Time-to-Live (TTL) that does not update」，write 公式为 input 加 5 分钟 storage。页未写明 storage/5 分钟不续期只适用于显式路径。src: https://openrouter.ai/docs/guides/best-practices/prompt-caching
- cache_write_tokens 何时出现：usage accounting 写「only returned for models with explicit caching and cache write pricing」（https://openrouter.ai/docs/cookbook/administration/usage-accounting）；overview 注释「Tokens written to cache (models with explicit caching)」（https://openrouter.ai/docs/api_reference/overview）。prompt caching 则把 cache_write_tokens 用于 OpenAI（含 GPT-5.6 自动 write）并写关掉缓存时该字段为 0（https://openrouter.ai/docs/guides/best-practices/prompt-caching）。
- 开头写 Alibaba 与 Anthropic「require you to enable it on a per-message basis」，Anthropic 节又允许顶层单个 cache_control，不是逐条 message。同页：https://openrouter.ai/docs/guides/best-practices/prompt-caching
- provider-selection 在 Anthropic beta 节写「Prompt caching and extended context are enabled based on model capabilities」（https://openrouter.ai/docs/guides/routing/provider-selection），与 prompt caching 页要求调用方提交 cache_control 才能开 Anthropic 缓存并立。未说明这句是只自动加 beta header，还是会注入 breakpoint。
- cache_discount 位置：prompt caching 说「The cache_discount field in the response body」但未点名端点；generation schema 有该字段；overview 的 ResponseUsage 未列 cache_discount。未裁决 chat 响应是否返回它。

## gaps
- 无统一 TTL 句。Grok、Moonshot、Groq、DeepSeek、Z.AI 以及 OpenAI 自动缓存的 TTL，prompt caching 页未给数字（只给了 OpenAI 显式最少 30 分钟、Anthropic 5 分钟/1 小时、Alibaba write 5 分钟、Gemini implicit 平均 3–5 分钟会变、以及另一节 Gemini write 5 分钟不续期）。
- 最小 token：页上有 OpenAI 1024、Anthropic 分模型、Gemini 2.5 Flash/Pro。Alibaba、Grok、Moonshot、Groq、DeepSeek、Z.AI 的最小粒度未写。
- 直接打到 Anthropic 第一方时 cache_control 是否字节级原样转发，页只写了 Bedrock 翻译与 OpenAI/Google 互转，没有 “as-is” 原句。
- 非 BYOK 的 usage.cost 相对上游 cache 价是否另加价，除已公布倍率与 BYOK 才返回 upstream_inference_cost 外，没有对照句。
- Messages API 是否同时返回规范化 cached_tokens，未核到原句。Chat usage 是否含 cache_read_input_tokens，overview 的 ResponseUsage 未列该字段，但是否运行时出现未单独再抓响应样例。
- https://openrouter.ai/docs/features/prompt-caching 本次打开已落到现行 prompt-caching 指南；搜索摘要里的旧句（OpenAI write 一律免费、Gemini 1028/2048）未当现行冲突。

## leads
- response cache 另用 X-OpenRouter-Cache / X-OpenRouter-Cache-TTL（默认 300 秒，1–86400）与 X-OpenRouter-Cache-Status: HIT|MISS；命中把 prompt/completion/total tokens 置 0。scope 是 API key，不是 prompt 前缀。
- Auto Exacto 会在 tool-calling 请求上重排 provider，可能中途打掉 sticky，造成 cache miss（https://openrouter.ai/docs/guides/routing/auto-exacto）。改模型 slug（如加上 :nitro）会使 sticky key 失效；前缀须 byte-identical（latency 页）。显式发送 temperature 等可能改变 provider-side cache key（parameters 页）。
- debug.echo_upstream_body 可回看改写后的上游 body。隐私 opt-in 的 1% 折扣不是 prompt cache 折扣。
