# r1-acp-zed
question: Zed 的 Agent Client Protocol（ACP）现行规范管什么：客户端与编码智能体如何对话、传输、方法名、鉴权、版本、谁治理，以及官方是否声明它不是 IBM 的 Agent Communication Protocol。
checked: https://agentclientprotocol.com, https://agentclientprotocol.com/llms.txt, https://agentclientprotocol.com/protocol/v1/overview, https://agentclientprotocol.com/protocol/v1/initialization, https://agentclientprotocol.com/protocol/v1/transports, https://agentclientprotocol.com/protocol/v1/authentication, https://agentclientprotocol.com/protocol/v1/session-setup, https://agentclientprotocol.com/get-started/architecture, https://agentclientprotocol.com/get-started/registry, https://agentclientprotocol.com/community/governance, https://agentclientprotocol.com/announcements/acp-v2-draft, https://zed.dev/acp, https://github.com/agentclientprotocol/agent-client-protocol, https://crystl.dev/blog/agent-communication-protocols/

## claims
- [C1] ACP 全称 Agent Client Protocol，规范 code editors/IDEs（Client 端）与 coding agents（Agent 端）之间的通信，本地与远程场景均适用。 | src: https://agentclientprotocol.com | quote: "The Agent Client Protocol (ACP) standardizes communication between code editors/IDEs and coding agents and is suitable for both local and remote scenarios." | type: official
- [C2] Agent 端定义：用生成式 AI 自主改代码的程序，通常作为 Client 的子进程运行。 | src: https://agentclientprotocol.com/protocol/v1/overview | quote: "Agents are programs that use generative AI to autonomously modify code. They typically run as subprocesses of the Client." | type: official
- [C3] Client 端定义：用户与 agent 之间的界面，通常是代码编辑器，管理环境、用户交互与资源访问。 | src: https://agentclientprotocol.com/protocol/v1/overview | quote: "They are typically code editors (IDEs, text editors) but can also be other UIs... Clients manage the environment, handle user interactions, and control access to resources." | type: official
- [C4] 通信模型为 JSON-RPC 2.0：方法（请求-响应）加通知（单向）。 | src: https://agentclientprotocol.com/protocol/v1/overview | quote: "The protocol follows the JSON-RPC 2.0 specification with two types of messages: Methods: Request-response pairs... Notifications: One-way messages that don't expect a response" | type: official
- [C5] Agent 侧 baseline 方法：initialize、authenticate、session/new、session/prompt；可选 session/load、logout、session/set_mode；通知 session/cancel。 | src: https://agentclientprotocol.com/protocol/v1/initialization | quote: "all Agents MUST support `session/new`, `session/prompt`, `session/cancel`, and `session/update`." | type: official
- [C6] 更多可选 session 生命周期方法经能力协商开启：session/resume、session/close、session/delete、session/list。 | src: https://agentclientprotocol.com/protocol/v1/session-setup | quote: "Agents that advertise `sessionCapabilities.resume` allow Clients to reconnect to an existing session without replaying the conversation history." | type: official
- [C7] Client 侧方法：session/request_permission（baseline），可选 fs/read_text_file、fs/write_text_file、terminal/create、terminal/output、terminal/release、terminal/wait_for_exit、terminal/kill、elicitation/create；Agent→Client 通知 session/update。 | src: https://agentclientprotocol.com/protocol/v1/overview | quote: "All `terminal/*` methods are available, allowing the Agent to execute and manage shell commands." | type: official
- [C8] transport：JSON-RPC 消息必须 UTF-8；当前定义的传输为 stdio（子进程 stdin/stdout，换行分隔、不得含内嵌换行）；Streamable HTTP 仍是 draft proposal；允许自定义传输。 | src: https://agentclientprotocol.com/protocol/v1/transports | quote: "ACP uses JSON-RPC to encode messages. JSON-RPC messages MUST be UTF-8 encoded." | type: official
- [C9] discovery/启动：编辑器按需拉起 agent 子进程，全部通信走 stdin/stdout；无网络服务发现。 | src: https://agentclientprotocol.com/get-started/architecture | quote: "the editor boots the agent sub-process on demand, and all communication happens over stdin/stdout." | type: official
- [C10] ACP Registry 是官方策展的 agent 发现/安装目录，只收录支持鉴权的 agent，仓库在 github.com/agentclientprotocol/registry。 | src: https://agentclientprotocol.com/get-started/registry | quote: "This is a curated set of agents, including only the ones that support authentication." | type: official
- [C11] 规范定义了鉴权：initialize 响应里 Agent 用 authMethods 广告方法（默认 type "agent"，另有 "terminal" 类型），Client 调 authenticate(methodId)；logout 由 agentCapabilities.auth.logout 开启。 | src: https://agentclientprotocol.com/protocol/v1/authentication | quote: "Agents advertise authentication options in the `authMethods` field of the `initialize` response." | type: official
- [C12] state：会话状态在 Agent 侧——session 维护自己的 context/历史，session/new 返回 sessionId，loadSession 能力支持跨重启持久化与回放。 | src: https://agentclientprotocol.com/protocol/v1/session-setup | quote: "Each session maintains its own context, conversation history, and state, allowing multiple independent interactions with the same Agent." | type: official
- [C13] version：现行稳定协议版本为整数 1，经 initialize 的 protocolVersion 协商；仅 breaking change 才递增 MAJOR。 | src: https://github.com/agentclientprotocol/agent-client-protocol | quote: "The current stable ACP protocol version is `1`." | type: official
- [C14] v2 于 2026-07-20 以 Draft 发布，不稳定；官方建议实现并行支持 v1+v2，schema 以 v2.0.0-alphaX 发布。 | src: https://agentclientprotocol.com/announcements/acp-v2-draft | quote: "v2 is a Draft... However, various pieces can, and will, change before stabilization." | type: official
- [C15] governance：ACP 由 Zed 与 JetBrains 联合治理，目标是过渡到独立基金会；两位 lead maintainer（BDFL）：Ben Brandt (Zed Industries) 与 Sergey Ignatov (JetBrains)；变更走 RFD（Requests for Dialog）流程。 | src: https://agentclientprotocol.com/community/governance | quote: "ACP is jointly governed by Zed and JetBrains... while working toward transitioning to an independent foundation." | type: official
- [C16] 许可与仓库：Apache 2.0、无 CLA；主仓库 github.com/agentclientprotocol/agent-client-protocol；官方 SDK：Rust、TypeScript、Python、Kotlin、Java。 | src: https://agentclientprotocol.com/community/governance | quote: "All repositories in the ACP organization should be licensed under the Apache 2.0 License." | type: official
- [C17] 官网点名的 editors/clients：Zed、JetBrains IDEs、Visual Studio Code、Neovim、Emacs、Obsidian、AionUi、marimo、Sidequery、DeepChat、Tidewave 等。 | src: https://zed.dev/acp | quote: "Created by Zed, grown by a community of editors and agents." | type: official
- [C18] 四大厂产品在官网/registry 均被点名：Claude Agent "ACP wrapper for Anthropic's Claude"（0.81.1）、Codex "ACP adapter for OpenAI's coding assistant"（1.13.1）、Gemini CLI "Google's official CLI for Gemini"（0.60.0）、GitHub Copilot "GitHub's AI pair programmer"（1.0.88）。 | src: https://agentclientprotocol.com/get-started/registry | quote: "ACP adapter for OpenAI's coding assistant" | type: official
- [C19] 官方把 ACP 类比 LSP。 | src: https://agentclientprotocol.com | quote: "providing a standardized protocol for agent-editor communication, similar to how the Language Server Protocol (LSP) standardized language server integration" | type: official
- [C20] 与 MCP 的关系：复用 MCP 的 JSON 类型，MCP 服务器配置由 Client 在 session/new 时传给 Agent（mcpServers 字段）。 | src: https://agentclientprotocol.com/get-started/architecture | quote: "MCP-friendly: The protocol is built on JSON-RPC, and re-uses MCP types where possible" | type: official
- [C21] 二手对比资料明确区分两个 ACP：Zed 的 Agent Client Protocol（editor↔coding agent，JSON-RPC/stdio）与 IBM 的 Agent Communication Protocol（agent↔agent，REST，2025-08 并入 A2A，仓库已归档）。 | src: https://crystl.dev/blog/agent-communication-protocols/ | quote: "Same acronym, completely different layer, and this one is very much alive... It has nothing to do with agents talking to each other." | type: secondary

## conflicts
- 无（v1 stable vs v2 draft 是官方明确的版本分层，非冲突）。唯一张力：官网首页称远程 agent "communicating over HTTP or WebSocket"，但 transports 规范页只定义了 stdio，Streamable HTTP 标注 "draft proposal in progress"——远程传输规范尚未落地。

## gaps
- relation（官方层面）：官方站点与 README 未出现任何区分 IBM Agent Communication Protocol / A2A 的声明；checked 的 13 个官方页面及 llms.txt 全站索引均无 "IBM" 或 "A2A" 条目。只有二手来源（crystl.dev，C21）做了区分。
- 规范各页未标 last-updated 日期；版本时间只能从公告页取得（v2 draft 发布于 2026-07-20；v1 发布时间未在已查页面标注）。
- auth 格另注：规范定义的是 client↔agent 的用户鉴权（agent login），不定义 HTTP 传输层的加密/鉴权方案（远程传输仍 draft）。

## leads
- IBM ACP 一侧：仓库 github.com/i-am-bee/acp 已于 2025-08-27 归档并并入 Linux Foundation 的 A2A（lfaidata.foundation 公告）——交给负责 IBM/A2A 的 worker。
- RFD 列表（agentclientprotocol.com/rfds）即协议路线图，含 MCP-over-ACP、Streamable HTTP/WebSocket transport、session fork 等在议提案。
- crystl.dev 的 A2A/ACP/MCP 对比页可作 relation 格的二手引证来源。
