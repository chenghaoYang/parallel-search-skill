## claims
- [C1] 现行规范版本是 2026-07-28（latest 指向它，schema.ts 按此版本）；前一版为 2025-11-25，更早为 2025-06-18、2025-03-26、2024-11-05 | src: https://modelcontextprotocol.io/specification/latest | quote: "This specification defines the authoritative protocol requirements, based on the TypeScript schema in schema.ts (schema/2026-07-28)" | type: official
- [C2] 三方角色：Host=发起连接的 LLM 应用，Client=宿主内的连接器，Server=提供上下文与能力的服务 | src: https://modelcontextprotocol.io/specification/latest | quote: "**Hosts**: LLM applications that initiate connections; **Clients**: Connectors within the host application; **Servers**: Services that provide context and capabilities" | type: official
- [C3] 每个 client 与一个 server 是 1:1 关系；host 可运行多个 client 实例 | src: https://modelcontextprotocol.io/specification/2026-07-28/architecture | quote: "each client having a 1:1 relationship with a particular server" | type: official
- [C4] 2026-07-28 起 MCP 是无状态协议：每请求自包含、自带版本与能力 | src: https://modelcontextprotocol.io/specification/2026-07-28/architecture | quote: "MCP is a stateless protocol: every request is self-contained and carries its own protocol version and capabilities." | type: official
- [C5] Server 端能力对象：Resources（上下文/数据）、Prompts（模板消息）、Tools（模型可执行函数） | src: https://modelcontextprotocol.io/specification/latest | quote: "**Resources**: Context and data, for the user or the AI model to use; **Prompts**: Templated messages and workflows for users; **Tools**: Functions for the AI model to execute" | type: official
- [C6] 规范首页列出的 client 侧能力只剩 Elicitation | src: https://modelcontextprotocol.io/specification/latest | quote: "Clients may offer the following features to servers: **Elicitation**: Server-initiated requests for additional information from users" | type: official
- [C7] Roots、Sampling、Logging 在 2026-07-28 被标记 Deprecated（仍在规范内，至少 12 个月弃用窗口） | src: https://modelcontextprotocol.io/specification/2026-07-28/changelog | quote: "Deprecate the Roots, Sampling, and Logging features (SEP-2577). These features remain fully functional during the deprecation window but new implementations should not add support for them." | type: official
- [C8] Completion 仍是现行 server utility：能力名 completions，方法 completion/complete | src: https://modelcontextprotocol.io/specification/2026-07-28/server/utilities/completion | quote: "clients send a `completion/complete` request specifying what is being completed through a reference type" | type: official
- [C9] 发现机制改为 server/discover：server 必须实现，返回 supportedVersions、capabilities、serverInfo；client 可选调用 | src: https://modelcontextprotocol.io/specification/2026-07-28/server/discover | quote: "`server/discover` lets a client query a server's supported protocol versions, capabilities, and identity before sending any other requests. Servers **MUST** implement it." | type: official
- [C10] initialize 握手在 2026-07-28 被移除；版本与能力改为每请求经 _meta 字段携带 | src: https://modelcontextprotocol.io/specification/2026-07-28/changelog | quote: "Make MCP stateless: remove the `initialize`/`notifications/initialized` handshake. Every request now carries its protocol version and client capabilities in `_meta`" | type: official
- [C11] 列举方法名 tools/list、resources/list、prompts/list 仍然存在 | src: https://modelcontextprotocol.io/specification/2026-07-28/changelog | quote: "List endpoints (`tools/list`, `resources/list`, `prompts/list`) no longer vary per-connection." | type: official
- [C12] 标准传输只有两个：stdio（子进程标准流上的换行分隔 JSON-RPC）与 Streamable HTTP（单端点 POST） | src: https://modelcontextprotocol.io/specification/2026-07-28/basic/transports | quote: "1. stdio: newline-delimited messages over the standard streams of a client-launched subprocess. 2. - [C13] HTTP+SSE 传输（2024-11-05 版）自 2025-03-26 起 deprecated，现按特性生命周期列为 Deprecated（SEP-2596） | src: https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http | quote: "The HTTP+SSE transport from protocol version 2024-11-05 has been deprecated since protocol version `2025-03-26` and is classified as Deprecated under the feature lifecycle policy (SEP-2596). - [C14] 但 SSE 作为响应格式仍在现行传输内：Streamable HTTP 的回复可以是请求级 SSE 流（text/event-stream） | src: https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http | quote: "The server answers each request with either a single JSON object or a Server-Sent Events (SSE) stream scoped to that request, carrying request-related notifications followed by the final response." | type: official
- [C15] Streamable HTTP 在 2025-03-26 引入，替代 2024-11-05 的 HTTP+SSE 传输 | src: https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http | quote: "Streamable HTTP was introduced in protocol version 2025-03-26 as a replacement for the HTTP+SSE transport from protocol version 2024-11-05." | type: official
- [C16] 2026-07-28 移除了 GET 流端点与协议级会话；SSE 可恢复性（Last-Event-ID）不再支持 | src: https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http | quote: "Removal of the GET stream endpoint. - [C17] 鉴权为可选；HTTP 传输方案基于 OAuth 2.1 草案，stdio 应取环境凭据 | src: https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization | quote: "Authorization is **OPTIONAL** for MCP implementations. - [C18] token 用 Authorization: Bearer 头发送；MCP server 必须实现 RFC9728 Protected Resource Metadata，401 用 WWW-Authenticate 携带 resource_metadata | src: https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization | quote: "MCP servers **MUST** implement OAuth 2.0 Protected Resource Metadata (RFC9728)." ; "`Authorization: Bearer <access-token>`" | type: official
