- [C3] lock：PEP 751 `pylock.toml` 只支持“导出”，由插件 poetry-plugin-export 提供，Poetry 2.3.0 加入；非原生锁格式。 | src: https://github.com/python-poetry/poetry/blob/main/CHANGELOG.md | quote: "Add support for exporting `pylock.toml` files with `poetry-plugin-export`" (2.3.0, 2026-01-18) | type: official

## conflicts
- pyver 表述张力：basic-usage 写 "Poetry will not install a Python interpreter for you"（https://python-poetry.org/docs/basic-usage/），而 CLI 页 2.1.0 起提供 `poetry python install`（"installs the specified Python version from the Python Standalone Builds project"，https://python-poetry.org/docs/cli/）。前者语境是不会“自动”安装，后者是手动实验命令；页面各自表述未同步。
- poetry-core 版本约束示例不一：docs/pyproject PEP-517 段示例 `requires = ["poetry-core>=1.0.0"]`；`poetry new` 实际生成 `>=2.0.0,<3.0.0`（basic-usage 模板 + changelog #9812 "Limit build-system to the current major version"）。

## gaps
- workspace：官方文档无任何 workspace/monorepo 配置键（sitemap 15 页全无该词）；无官方说法可引，属“文档没有”而非“文档说没有”。
- migrate：无官方命令/文档支持从 pipenv/requirements.txt/pyproject(pip) 自动迁入；`poetry init` 仅为交互式问答。
- cicache：官方文档未给出 GitHub Actions/GitLab CI 的缓存 key/路径示例（如缓存 .venv 还是 cache-dir 的推荐），只有 Docker 分层技巧和 POETRY_CACHE_DIR。
- lock：未见官方说明 `poetry install/lock` 能否直接读写 `pylock.toml`（仅有 export 插件导出）。

## leads
- Poetry 2.2.0 起支持 PEP 735 `[dependency-groups]` 与嵌套依赖组（CHANGELOG），与 tool.poetry.group 并存，若大题涉及依赖组写法可查 dependency-specification/managing-dependencies。
- `installer.re-resolve` 默认 2.3.0 起改为 false，靠锁文件内 markers/groups 直接安装，影响 CI 速度建议。
- 社区有非官方 workspace 插件（poetry-plugin-workspace 等），未在官方文档列出。
