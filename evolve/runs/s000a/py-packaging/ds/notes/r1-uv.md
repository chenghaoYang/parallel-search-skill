## claims
- [C1] lock：默认锁文件是 `uv.lock`，写在 `pyproject.toml` 旁；它是 universal/cross-platform 锁文件 | src: https://docs.astral.sh/uv/concepts/projects/layout/ | quote: "uv creates a `uv.lock` file next to the `pyproject.toml`. `uv.lock` is a *universal* or *cross-platform* lockfile" | type: official
- [C2] lock：`uv.lock` 是 uv 专有 TOML 格式，其他工具不能用 | src: https://docs.astral.sh/uv/concepts/projects/layout/ | quote: "The `uv.lock` format is specific to uv and not usable by other tools." | type: official
- [C3] lock：uv 读/装/生成 pylock.toml 的原样命令：`uv export -o pylock.toml`、`uv pip compile requirements.in -o pylock.toml`、`uv pip sync pylock.toml`、`uv pip install -r pylock.toml` | src: https://docs.astral.sh/uv/concepts/projects/layout/ | quote: "uv supports `pylock.toml` as an export target and in the `uv pip` CLI." | type: official
- [C4] lock：`uv export` 支持三种格式，`--format` 取值 `requirements.txt` / `pylock.toml` / `cyclonedx1.5`，`-o/--output-file` 写文件 | src: https://docs.astral.sh/uv/concepts/projects/export/ | quote: "The format can be specified with the `--format` flag: $ uv export --format requirements.txt $ uv export --format pylock.toml $ uv export --format cyclonedx1.5" | type: official
- [C5] lock：项目接口仍只用 uv.lock，pylock.toml 不能当项目锁文件 | src: https://docs.astral.sh/uv/concepts/projects/layout/ | quote: "uv will continue to use the `uv.lock` format within the project interface." | type: official
- [C6] lock：PEP 751 支持自 uv 0.6.15 起（changelog 称 preliminary） | src: https://github.com/astral-sh/uv/blob/main/changelogs/0.6.x.md | quote: "This release includes preliminary support for the `pylock.toml` file format, as standardized in PEP 751." | type: official
- [C7] lock：`uv lock` 显式建锁；`uv lock --check` 等价 `--locked`；`--frozen` 直接用锁不检查；`uv lock --upgrade` / `--upgrade-package <pkg>` 升级 | src: https://docs.astral.sh/uv/concepts/projects/sync/ | quote: "To use the lockfile without checking if it is up-to-date, use the `--frozen` option" | type: official
- [C8] meta：项目元数据在 `pyproject.toml` 的 `[project]` 表（PEP 621），最小为 name+version | src: https://docs.astral.sh/uv/concepts/projects/layout/ | quote: "Python project metadata is defined in a `pyproject.toml` file. uv requires this file to identify the root directory of a project." | type: official
- [C9] meta：依赖写在四个字段：`project.dependencies`、`project.optional-dependencies`、`dependency-groups`、`tool.uv.sources` | src: https://docs.astral.sh/uv/concepts/projects/dependencies/ | quote: "Dependencies of the project are defined in several fields: `project.dependencies`: Published dependencies. `project.optional-dependencies` ... `dependency-groups`: Local dependencies for development. `tool.uv.sources`" | type: official
- [C10] meta：开发依赖写 `[dependency-groups]`（PEP 735），`dev` 组默认被 sync；旧字段 `tool.uv.dev-dependencies` 仍兼容将废弃 | src: https://docs.astral.sh/uv/concepts/projects/dependencies/ | quote: "uv uses the `[dependency-groups]` table (as defined in PEP 735) for declaration of development dependencies." | type: official
- [C11] meta：`[tool.uv]` 存 uv 专属设置：`environments`、`required-environments`、`conflicts`、`package`、`default-groups`、`no-build-isolation-package`、`cache-keys` 等 | src: https://docs.astral.sh/uv/concepts/projects/config/ | quote: "you can constrain the set of solved platforms via the `environments` setting" | type: official
- [C12] workspace：表名 `[tool.uv.workspace]`，必填 `members`、可选 `exclude`，值为 glob 列表 | src: https://docs.astral.sh/uv/concepts/projects/workspaces/ | quote: "you must specify the `members` (required) and `exclude` (optional) keys, which direct the workspace to include or exclude specific directories" | type: official
- [C13] workspace：整个 workspace 共享一份锁文件 | src: https://docs.astral.sh/uv/concepts/projects/workspaces/ | quote: "the workspace shares a single lockfile, ensuring that the workspace operates with a consistent set of dependencies." | type: official
- [C14] workspace：`uv lock` 作用于整个 workspace；`uv run`/`uv sync` 默认作用根项目，`--package` 选成员 | src: https://docs.astral.sh/uv/concepts/projects/workspaces/ | quote: "`uv lock` operates on the entire workspace at once, while `uv run` and `uv sync` operate on the workspace root by default, though both accept a `--package` argument" | type: official
- [C15] workspace：成员间依赖在 `tool.uv.sources` 里标 `workspace = true` | src: https://docs.astral.sh/uv/concepts/projects/workspaces/ | quote: "bird-feeder = { workspace = true }" | type: official
- [C16] pyver：安装解释器 `uv python install 3.12`（可装多个/约束/实现如 pypy） | src: https://docs.astral.sh/uv/concepts/python-versions/ | quote: "To install a Python version at a specific version: $ uv python install 3.12.3" | type: official
- [C17] pyver：`uv python pin` 在当前目录写 `.python-version`；`uv python pin --global` 写用户级 | src: https://docs.astral.sh/uv/concepts/python-versions/ | quote: "A `.python-version` file can be created in the current directory with the `uv python pin` command." | type: official
- [C18] pyver：项目用 `project.requires-python` 声明版本范围；命令可用 `--python` 指定；环境变量 `UV_PYTHON` 可覆盖 | src: https://docs.astral.sh/uv/concepts/python-versions/ | quote: "uv will respect Python requirements defined in `requires-python` in the `pyproject.toml` file during project command invocations." | type: official
- [C19] backend：uv 自带原生 build backend `uv_build`，`build-backend = "uv_build"`，requires 形如 `uv_build>=0.12.18,<0.13`（文档示例，页更新 2026-09-22） | src: https://docs.astral.sh/uv/concepts/build-backend/ | quote: "uv also provides a native build backend (`uv_build`) that integrates tightly with uv" | type: official
- [C20] backend：`uv init` 默认用 uv build backend；`--build-backend` 换其他后端；`--no-package` 不打包 | src: https://docs.astral.sh/uv/concepts/projects/config/ | quote: "By default, `uv init` creates a packaged project using the uv build backend. The `--build-backend` option can be provided to select an alternative build backend" | type: official
- [C21] backend：uv_build 只支持纯 Python；扩展模块需换后端（文档建议 hatchling） | src: https://docs.astral.sh/uv/concepts/build-backend/ | quote: "The uv build backend currently **only supports pure Python code**." | type: official
- [C22] index：私有/额外 index 配置在 `[[tool.uv.index]]` 表，键 `name` + `url`；CLI 对应 `--index` | src: https://docs.astral.sh/uv/concepts/indexes/ | quote: "uv can be configured to use other package indexes, including private indexes, via the `[[tool.uv.index]]` configuration option (and `--index`, the analogous command-line option)." | type: official
- [C23] index：`default = true`（或 `--default-index`）替换 PyPI 为默认；`explicit = true` 使 index 仅供 `tool.uv.sources` pin 的包用 | src: https://docs.astral.sh/uv/concepts/indexes/ | quote: "An index can be marked as `explicit = true` to prevent packages from being installed from that index unless explicitly pinned to it." | type: official
- [C24] index：环境变量 `UV_INDEX`、`UV_DEFAULT_INDEX`；凭证用 `UV_INDEX_<NAME>_USERNAME`/`UV_INDEX_<NAME>_PASSWORD`（名大写、非字母数字转下划线）或嵌进 URL；也支持 netrc/keyring，`authenticate = "always"|"never"` | src: https://docs.astral.sh/uv/concepts/indexes/ | quote: "you can set the `UV_INDEX_INTERNAL_PROXY_USERNAME` and `UV_INDEX_INTERNAL_PROXY_PASSWORD` environment variables" | type: official
- [C25] index：多 index 策略 `--index-strategy` / `UV_INDEX_STRATEGY`：`first-index`（默认）、`unsafe-first-match`、`unsafe-best-match` | src: https://docs.astral.sh/uv/concepts/indexes/ | quote: "use the`--index-strategy` command-line option, or the `UV_INDEX_STRATEGY` environment variable" | type: official
- [C26] cicache：缓存目录按序取 `--cache-dir`、`UV_CACHE_DIR`、`tool.uv.cache-dir`，否则 `$XDG_CACHE_HOME/uv`/`$HOME/.cache/uv`（Win `%LOCALAPPDATA%\uv\cache`） | src: https://docs.astral.sh/uv/concepts/cache/ | quote: "The specific cache directory specified via `--cache-dir`, `UV_CACHE_DIR`, or `tool.uv.cache-dir`." | type: official

## conflicts
- 无实质冲突。唯一措辞差：layout 页写 `uv export -o pylock.toml`，export 页写 `uv export --format pylock.toml --output-file pylock.toml`，同一功能两种等价写法（-o 按扩展名推断格式），非冲突。
