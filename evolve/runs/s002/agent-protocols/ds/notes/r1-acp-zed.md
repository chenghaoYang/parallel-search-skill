# r1-acp-zed
question: Zed 的 Agent Client Protocol（ACP）官方现在规定谁和谁说话、有哪些 JSON-RPC 方法、传输、能力协商、鉴权、版本、谁治理，以及它和 IBM/BeeAI 的 Agent Communication Protocol、和 MCP 是不是同一个协议。
checked: https://agentclientprotocol.com/get-started/introduction, https://agentclientprotocol.com/protocol/v1/overview, https://agentclientprotocol.com/protocol/v1/initialization, https://agentclientprotocol.com/protocol/v1/transports, https://agentclientprotocol.com/protocol/v1/authentication, https://agentclientprotocol.com/get-started/architecture, https://agentclientprotocol.com/community/governance, https://agentclientprotocol.com/announcements/acp-v2-draft, https://agentclientprotocol.com/llms.txt, https://github.com/agentclientprotocol/agent-client-protocol, https://zed.dev/acp

## claims
- [C1] 本侧官方全名是 "Agent Client Protocol (ACP)"，用途是标准化代码编辑器/IDE 与 coding agent 之间的通信 | src: https://agentclientprotocol.com/get-started/introduction | quote: "The Agent Client Protocol (ACP) standardizes communication between code editors/IDEs and coding agents and is suitable for both local and remote scenarios." | type: official
- [C2] ACP 定位为编辑器↔agent 协议，类比 LSP | src: https://agentclientprotocol.com/get-started/introduction | quote: "similar to how the [Language Server Protocol (LSP)](...) standardized language server integration" | type: official
- [C3] 通信双方：Client（通常是代码编辑器）与 Agent（用生成式 AI 自主改代码的程序，通常作为 Client 的子进程），双方都可暴露方法并互发通知 | src: https://agentclientprotocol.com/protocol/v1/overview | quote: "Agents are programs that use generative AI to autonomously modify code. They typically run as subprocesses of the Client." / "Clients ... are typically code editors (IDEs, text editors)" | type: official
- [C4] 协议基于 JSON-RPC 2.0，有 methods（请求-响应）和 notifications（单向）两类消息 | src: https://agentclientprotocol.com/protocol/v1/overview | quote: "The protocol follows the [JSON-RPC 2.0](https://www.jsonrpc.org/specification) specification with two types of messages" | type: official
- [C5] Agent 侧 baseline 方法：initialize、authenticate、session/new、session/prompt；可选：session/load（需 loadSession 能力）、logout（需 agentCapabilities.auth.logout）、session/set_mode；通知：session/cancel | src: https://agentclientprotocol.com/protocol/v1/overview | quote: "Baseline Methods ... initialize ... authenticate ... session/new ... session/prompt" | type: official
- [C6] Client 侧 baseline 方法：session/request_permission（agent 请求用户授权工具调用）；可选：fs/read_text_file、fs/write_text_file、terminal/create、terminal/output、terminal/release、terminal/wait_for_exit、terminal/kill、elicitation/create；通知：elicitation/complete、session/update | src: https://agentclientprotocol.com/protocol/v1/overview | quote: "session/request_permission ... Request user authorization ... for tool calls" | type: official
- [C7] 权限流：prompt turn 中 Agent→Client 发文件操作或权限请求，Client→Agent 可发 session/cancel 中断 | src: https://agentclientprotocol.com/protocol/v1/overview | quote: "Agent → Client: File operations or permission requests as needed ... Client → Agent: `session/cancel` to interrupt processing if needed" | type: official
- [C8] 传输：stdio 是当前定义的传输（client 把 agent 拉成子进程，消息以 `\n` 分隔、不得含内嵌换行、UTF-8，stdout 只能写 ACP 消息，stderr 可写日志）；Streamable HTTP 仍是 draft proposal；允许自定义传输但须保持 JSON-RPC 格式与生命周期 | src: https://agentclientprotocol.com/protocol/v1/transports | quote: "The client launches the agent as a subprocess. ... Messages are delimited by newlines (`\n`), and **MUST NOT** contain embedded newlines." | type: official
- [C9] 版本协商：initialize 请求带 protocolVersion（单个整数，标识 MAJOR 版本，仅破坏性变更时递增）；agent 支持则回同一版本，否则回它支持的最新版本；client 不支持则 SHOULD 断开 | src: https://agentclientprotocol.com/protocol/v1/initialization | quote: "a single integer that identifies a **MAJOR** protocol version. This version is only incremented when breaking changes are introduced." | type: official
- [C10] 当前稳定协议版本为 1；线兼容性由 initialize 里协商的 protocolVersion 决定，与 crate/schema 发布版本无关 | src: https://github.com/agentclientprotocol/agent-client-protocol | quote: "**The current stable ACP protocol version is `1`.**" | type: official
- [C11] ACP v2 草案已发布（Published: July 20, 2026），schema 与文档以 draft 形式公开，作者署名 Ben Brandt（Zed Industries / ACP Lead Maintainer） | src: https://agentclientprotocol.com/announcements/acp-v2-draft | quote: "**first Draft of version 2 of the Agent Client Protocol** ... **v2 is a Draft**" | type: official
- [C12] 能力协商：initialize 交换 clientCapabilities（fs.readTextFile/writeTextFile、terminal、elicitation、auth.terminal 等）与 agentCapabilities（loadSession、promptCapabilities.image/audio/embeddedContext、mcpCapabilities.http/sse、auth.logout 等）；省略的能力 MUST 视为 UNSUPPORTED | src: https://agentclientprotocol.com/protocol/v1/initialization | quote: "Clients and Agents **MUST** treat all capabilities omitted in the `initialize` request as **UNSUPPORTED**." | type: official
- [C13] 鉴权：agent 在 initialize 响应的 authMethods 里广告方法；类型 `agent`（默认，client 调 authenticate 带 methodId）与 `terminal`（需 clientCapabilities.auth.terminal，client 另起交互进程跑登录）；logout 需 agentCapabilities.auth.logout 能力 | src: https://agentclientprotocol.com/protocol/v1/authentication | quote: "Agents advertise authentication options in the `authMethods` field of the `initialize` response." | type: official
- [C14] 治理：ACP 由 Zed 与 JetBrains 联合治理（interim model），目标是过渡到独立基金会；两名 lead maintainer（BDFL）：Ben Brandt（Zed Industries）与 Sergey Ignatov（JetBrains）；变更走 RFD（Requests for Dialog）流程 | src: https://agentclientprotocol.com/community/governance | quote: "ACP is jointly governed by Zed and JetBrains ... ACP has two lead maintainers: Ben Brandt (Zed Industries) and Sergey Ignatov (JetBrains)." | type: official
- [C15] 许可证：ACP 组织下所有仓库采用 Apache 2.0，无 CLA | src: https://agentclientprotocol.com/community/governance | quote: "All repositories in the ACP organization should be licensed under the Apache 2.0 License." | type: official
- [C16] 起源：ACP 由 Zed 创建 | src: https://zed.dev/acp | quote: "Created by Zed, grown by a community of editors and agents." | type: official
- [C17] 与 MCP 关系：ACP 复用 MCP 的 JSON 表示，但二者不同层——编辑器把用户配置的 MCP server 配置随 prompt 传给 agent，agent 直连 MCP server；ACP 是 editor↔agent 通道，MCP 是 agent↔工具通道 | src: https://agentclientprotocol.com/get-started/architecture | quote: "Commonly the code editor will have user-configured MCP servers. When forwarding the prompt from the user, it passes configuration for these to the agent. This allows the agent to connect directly to the MCP server." | type: official
- [C18] 同上，设计原则明确 "MCP-friendly" | src: https://agentclientprotocol.com/get-started/architecture | quote: "**MCP-friendly**: The protocol is built on JSON-RPC, and re-uses MCP types where possible" | type: official
- [C19] schema 仓库与产物：github.com/agentclientprotocol/agent-client-protocol，JSON Schema 在 schema/v1 与 schema/v2，发布时附到 GitHub releases；Rust crate agent-client-protocol-schema / agent-client-protocol，TS 包 @agentclientprotocol/sdk | src: https://github.com/agentclientprotocol/agent-client-protocol | quote: "Generated JSON Schema artifacts live in [`schema/v1`](...) and [`schema/v2`](...)" | type: official
- [C20] 扩展机制：自定义数据用 _meta 字段，自定义方法名加下划线前缀，初始化时可广告自定义能力；属性键 camelCase，discriminator 值 snake_case；文件路径必须绝对路径，行号 1-based | src: https://agentclientprotocol.com/protocol/v1/overview | quote: "Add custom data using `_meta` fields ... Create custom methods by prefixing their name with underscore (`_`)" | type: official

## conflicts
- 无官方文档间冲突。注意版本差异（非冲突）：v1 用 session/load、logout、turn 式 session/prompt；v2 draft 改名/改语义（session/resume、auth/logout、prompt 返回 messageId、session/update 可在 turn 外发）。本笔记方法名以 v1 stable 为准。
