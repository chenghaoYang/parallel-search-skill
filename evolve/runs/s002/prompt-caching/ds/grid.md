# Taxonomy 网格

状态：`✅` 一手来源+原句；`⚠` 只有二手；`⚔` 来源冲突；`❓` 缺口；`∅` 官方未写（已定向查过）；`—` 不适用。

## 分类轴

v0 → v1（R1 收束）：轴从「标记放在请求里还是独立资源」改成 **默认路径要不要在请求里放缓存标记**。

v0 把 OpenAI 只放进「隐式前缀」，但现行指南同时有默认 implicit 和 `mode=explicit`（不放断点则不缓存）。新轴解释用户的疑点（改不改代码）。写入溢价解释不了这个轴：OpenAI GPT-5.6+ 默认零标记，仍然收 1.25× 写费。计费留在 D5，不并进家族。

| 家族 | 默认路径 | R1 成员 |
|---|---|---|
| F-自动 | 不改请求就可能命中 | OpenAI（默认 implicit）、DeepSeek、Gemini 隐式 |
| F-标记 | 请求里要出现缓存标记才进入文档里的启用路径 | Anthropic（顶层或块级 `cache_control`） |
| F-资源 | 先创建 cache 对象，再在请求里引用 | Gemini 显式 |
| F-网关 | prompt cache 在上游；网关转译标记并做粘性路由 | OpenRouter |

OpenAI 的 explicit 模式是 F-自动厂商里的可选开关，不另开一行。

## 维度

| 列 | 问题 |
|---|---|
| D1 触发 | 要不要改请求？改哪个字段或先调哪个端点？ |
| D2 缓存键 | 比的是前缀哈希还是 cache 资源名？键里含哪些部分？ |
| D3 门槛 | 短于多少 token 不会写或不会命中？ |
| D4 TTL | 默认活多久，能否改，固定还是滑动？ |
| D5 计费 | 写入价、读取价相对普通 input；未命中有无额外费？ |
| D6 命中信号 | 响应里哪个字段表示命中了多少 token？ |
| D7 失效 | 哪些改动让原本可命中的前缀失效？ |
| D8 范围 | system / tools / messages / 多模态 / 多轮追加，哪些能进缓存？ |
| D9 覆盖 | 哪些模型、哪条 API；命中是尽力而为还是可预期？ |
