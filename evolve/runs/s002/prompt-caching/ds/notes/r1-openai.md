# r1-openai
question: OpenAI API 的 prompt caching 现在怎么触发、怎么计费、能活多久、响应里怎么看见命中、什么会让缓存失效。
checked: https://developers.openai.com/api/docs/guides/prompt-caching, https://developers.openai.com/api/docs/pricing, https://developers.openai.com/api/reference/resources/responses/methods/create, https://developers.openai.com/api/reference/resources/chat.md (POST /chat/completions reference), https://developers.openai.com/api/docs/changelog.md

## conflicts
- API reference 称 prompt_cache_retention 对 "gpt-5.5, gpt-5.5-pro, and future models, only `24h` is supported"（https://developers.openai.com/api/reference/resources/responses/methods/create）；但 guide 中 GPT-5.6+ 改用 prompt_cache_options.ttl="30m"、不再列 24h（https://developers.openai.com/api/docs/guides/prompt-caching）。"future models" 措辞与 5.6 的 30m ttl 不完全一致。
- Guide 写 lookup 边界为 "first 2 and latest 50 explicit breakpoints" 等；API reference 写 "considers up to the latest 80 breakpoints in the conversation"——粒度不同，未直接矛盾但数字不一致。

## gaps
- 更早模型各自的最小可缓存 token 数（guide 只说 "varies by request settings"，无逐模型数字）；路由 hash 的具体前缀长度（搜索摘要称 ~256 tokens，guide 正文只说 varies by model，未取到原句）。
- Chat Completions 的 prompt_cache_options 不含 prewarm/comparison_response_id（reference 只列 {mode, ttl}），prewarm 似为 Responses 独有——未在 guide 找到明确排他句。
