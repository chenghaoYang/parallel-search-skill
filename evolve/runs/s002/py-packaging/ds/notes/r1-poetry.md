## conflicts
- 无硬冲突。注意措辞差异：2.0 公告说 "many fields in the tool.poetry section are deprecated"，但 pyproject 页中 version/readme/classifiers 未标 Deprecated，只写 "prefer project.*"（因 dynamic 场景仍需）。另 `installer.re-resolve` 默认 true（2.0 公告）→ false（2.3.0 起），属版本变更非矛盾。

## gaps
- 官方文档中不存在 workspace/monorepo 功能名或专页（已查 cli 全命令列表、pyproject、dependency-specification、faq、configuration 各页；site 搜索 "workspace" 无官方文档命中）——只能间接确认，最接近机制为 C14 的 path 依赖。
- Poetry 是否会读取/尊重已存在的 pylock.toml：官方只明确说 "not yet able to replace poetry.lock"，未找到「读取 pylock.toml」的原句。
- poetry.lock 内部格式版本：配置页提到 "lock file is at least version 2.1 (created by Poetry 2.0 or above)"，未见完整格式规范页。

## leads
- poetry-plugin-export >=1.10.0 支持 `poetry export -f pylock.toml`（插件仓库 README，一手插件源：https://github.com/python-poetry/poetry-plugin-export）。
- PEP 735 [dependency-groups] + include-group 是 2.2+ 官方功能，和 grid 的 group 语义相关。
- 社区插件 poetry-multiproject-plugin / poetry-monoranger-plugin 补 workspace 空白（二手，未经官方背书）。
- `virtualenvs.use-poetry-python`（2.0 新增，默认 false）控制用哪个解释器建 venv。
