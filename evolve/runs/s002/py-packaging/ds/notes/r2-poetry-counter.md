## conflicts
- D 被推翻：PDM build 页称 "poetry-core is not supported because it does not support reading PEP 621 metadata"（https://pdm-project.org/en/latest/reference/build/），但 poetry-core CHANGELOG 2.0.0（2025-01-04）写明 "Add support for the `project` section in the `pyproject.toml` file according to PEP 621"（https://raw.githubusercontent.com/python-poetry/poetry-core/main/CHANGELOG.md）。PDM 的理由对 poetry-core <2.0 成立，对 2.x 已过时；PDM 自身是否已支持 poetry-core 未查（超范围）。
- B 的排他性被推翻且官方文档自相矛盾：dependency-specification 页（docs 2.5）仍写 "Only main dependencies can be specified in the `project` section. Other Dependency groups must still be specified in the `tool.poetry` section"（https://python-poetry.org/docs/dependency-specification/），但 2.2.0 公告与 managing-dependencies 页均写明组可用 PEP 735 `[dependency-groups]`（https://python-poetry.org/blog/announcing-poetry-2.2.0/、https://python-poetry.org/docs/managing-dependencies/）。
- A、C 未找到反例：2.1–2.5 全部公告 + 现行文档均未把 tool.poetry.dependencies 标为 Deprecated，pylock.toml 仍是仅可导出、不能替代 poetry.lock。

## gaps
- 「未废弃 tool.poetry.dependencies」「无 workspace」「poetry.lock 未被替换」均属否定主张：已逐页查 2.1.0/2.2.0/2.3.0/2.4.0/2.5.0 公告全文、docs 2.5 的 pyproject/dependency-specification/managing-dependencies/FAQ、poetry-core CHANGELOG 与 README，未见相反条目；但 web_fetch 返回为摘要，无法 100% 排除页面细节遗漏。
- poetry-plugin-export 的 pylock 导出是否需要 PEP 751 读取端支持、Poetry 本体何时能读 pylock.toml，公告未给时间表。

## leads
- Poetry 2.5.0（2026-09-19）已发布：内置 uninstaller、性能改进；2.4.0 加 solver.min-release-age 供应链防护——若主表需要「最新版本」行可用。
- poetry-core 2.0.1 修复 "dynamic `project.dependencies` via `tool.poetry.dependencies` were ignored"：project+tool.poetry 混合模式有真实 bug 史，meta 格可注明。
- 2.1 起 `poetry build` 可用第三方后端（maturin 等），build 格里 poetry-core 独占说法已过时。
