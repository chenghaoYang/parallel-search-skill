# r1-acp-zed
question: Zed 的 Agent Client Protocol（ACP）现行规范：连接谁、交换什么、传输、会话状态、发现、鉴权、版本、谁治理、官方怎么描述它和 MCP / LSP 的关系（grid 实体 ACP-Zed 的 D1–D9）

## claims
- [C1] 全名 Agent Client Protocol（ACP），标准化 code editor/IDE 与 coding agent 之间的通信，适用于本地与远程场景 | src: https://agentclientprotocol.com | quote: 「The Agent Client Protocol (ACP) standardizes communication between code editors/IDEs and coding agents and is suitable for both local and remote scenarios.」 | type: official
- [C2] D1 Client 角色：Client 是用户与 agent 之间的界面，典型为 code editor（IDE、文本编辑器），也可以是其他 UI；Zed 即 Client | src: https://agentclientprotocol.com/protocol/v1/overview.md | quote: 「Clients provide the interface between users and agents. - [C3] D1 Agent 角色：Agent 是用生成式 AI 自主修改代码的程序，通常作为 Client 的子进程运行 | src: https://agentclientprotocol.com/protocol/v1/overview.md | quote: 「Agents are programs that use generative AI to autonomously modify code. They typically run as subprocesses of the Client.」 | type: official
- [C4] D2 通信模型遵循 JSON-RPC 2.0，分 Methods（请求-响应）与 Notifications（单向）两类消息 | src: https://agentclientprotocol.com/protocol/v1/overview.md | quote: 「The protocol follows the JSON-RPC 2.0 specification with two types of messages: Methods: Request-response pairs ... - [C5] D2 Agent 侧 baseline 方法：`initialize`、`authenticate`、`session/new`、`session/prompt`；可选方法 `session/load`（需 `loadSession` capability）、`logout`、`session/set_mode`；通知 `session/cancel` | src: https://agentclientprotocol.com/protocol/v1/overview.md | quote: 「Baseline Methods ... initialize ... authenticate ... session/new ... session/prompt ... Agents that advertise `sessionCapabilities.close` allow Clients to tell the Agent to cancel any ongoing work」 | type: official
- [C7] D2 Client 侧方法：baseline `session/request_permission`；可选 `fs/read_text_file`、`fs/write_text_file`、`terminal/create`、`terminal/output`、`terminal/release`、`terminal/wait_for_exit`、`terminal/kill`、`elicitation/create`；Client 侧收到的通知含 `session/update`、`elicitation/complete` | src: https://agentclientprotocol.com/protocol/v1/overview.md | quote: 「session/request_permission ... fs/read_text_file ... fs/write_text_file ... terminal/create ... terminal/output ... terminal/release ... terminal/wait_for_exit ... terminal/kill ... elicitation/create ... elicitation/complete ... session/update」 | type: official
- [C8] D3 ACP 用 JSON-RPC 编码消息，MUST 为 UTF-8；v1 正式定义的传输只有 stdio；Streamable HTTP 标注为 draft proposal in progress；允许 custom transports | src: https://agentclientprotocol.com/protocol/v1/transports.md | quote: 「The protocol currently defines the following transport mechanisms ... 1. stdio ... 2. - [C9] D3 stdio 传输：client 以子进程启动 agent，JSON-RPC 消息走 stdin/stdout，以换行 `\n` 分隔、不得含内嵌换行；stderr 可用于日志 | src: https://agentclientprotocol.com/protocol/v1/transports.md | quote: 「The client launches the agent as a subprocess. ... - [C10] D4 session 状态在 Agent 端：`session/new` 后 Agent 创建 session context 并连接 MCP server，返回 `sessionId`；每个 session 维护自己的 context、conversation history 与 state | src: https://agentclientprotocol.com/protocol/v1/session-setup.md | quote: 「Each session maintains its own context, conversation history, and state, allowing multiple independent interactions with the same Agent.」 | type: official

- [C12] D4 `session/prompt` 响应带 `stopReason`，枚举值：`end_turn`、`max_tokens`、`max_turn_requests`、`refusal`、`cancelled` | src: https://agentclientprotocol.com/protocol/v1/prompt-turn.md | quote: 「the Agent MUST respond to the original `session/prompt` request with a `StopReason`」 | type: official
- [C13] D5 能力协商在 `initialize`：Client 发送 `protocolVersion` 与 `clientCapabilities`（如 `fs.readTextFile`、`terminal`、`elicitation`、`auth.terminal`），Agent 回 `agentCapabilities`（如 `loadSession`、`promptCapabilities`、`mcpCapabilities`、`auth.logout`、`sessionCapabilities`）与 `authMethods` | src: https://agentclientprotocol.com/protocol/v1/initialization.md | quote: 「The Initialization phase allows Clients and Agents to negotiate protocol versions, capabilities, and authentication methods.」 | type: official

## conflicts
- 远程传输表述不一致：Introduction 页称「Remote agents ... communicating over HTTP or WebSocket」（https://agentclientprotocol.com），但 v1 Transports 页只定义 stdio、把 Streamable HTTP 标为 draft 且未列 WebSocket（https://agentclientprotocol.com/protocol/v1/transports.md）。Intro 同时注明「Full support for remote agents is a work in progress」，故更像未完成功能而非矛盾。

## gaps
- 远程传输的传输层鉴权/TLS/Token 未规定：v1 仅有 stdio 传输，鉴权章节只覆盖 agent 登录流程；Streamable HTTP/WebSocket 的鉴权待 transports RFD。
- v2 与 v1 的方法名差异未逐条核对（存在 protocol/v2/migration.md，未打开）。
- ACP Registry 的具体 API/清单格式未查（仅确认有 github.com/agentclientprotocol/registry 仓库与 curated 性质）。
