# Taxonomy 网格 v0

状态：`✅` 一手来源 + 原文摘录；`⚠` 只有二手；`⚔` 来源冲突；`❓` 缺口；`∅` 官方未写（已定向查过）；`—` 不适用。

## 分类轴

**主轴：谁控制缓存边界。** 这一轴直接回答用户的第一问（要不要改代码），也约束计费里有没有单独的「写入」和 TTL 能不能由调用方指定。

| 家族 | 判据 | 预期成员（待 R1/R2 核实，不是结论） |
|---|---|---|
| 自动前缀 | 请求里没有缓存字段，服务端对从开头算起的稳定前缀自动缓存 | OpenAI、DeepSeek；Gemini 隐式模式；待核 Kimi / 智谱 / 千问 |
| 请求内断点 | 调用方在消息或内容块上打标记，标记之前的前缀才缓存 | Anthropic `cache_control`；待核谁兼容该字段 |
| 命名缓存资源 | 先单独创建缓存对象，后续请求引用其名字 | Gemini 显式 context caching；待核千问显式缓存是否同形 |
| 网关 | 自己不定义唯一语义，按上游透传或做字段映射 | OpenRouter |

一个厂商可以占两行（Gemini 隐式 / 显式）。次轴先不拆行：**写入是否另收费**（只打折读取 vs 写入加价或按存储计费）。若 R1 显示它比主轴更能解释矩阵，收束时换轴。

## 维度（每一列回答一个问题）

| ID | 维度 | 这一列回答什么 |
|---|---|---|
| D1 | 接入 | 不改现有请求能不能命中？要改的话，是哪个字段，还是先调用哪个创建接口？ |
| D2 | 缓存边界 | 被缓存的单位是什么？从请求的哪一段算到哪一段？ |
| D3 | 命中门槛 | 最少多少 token 才写入或才可能命中？前缀要一致到哪（system、tools、messages、多模态）？ |
| D4 | 计费 | cache read、cache write、存储（若有）相对普通 input 的口径；未命中是否另收费？ |
| D5 | TTL | 默认活多久？能否指定？命中或再写会不会续期？ |
| D6 | 观测 | 响应里哪个字段或 header 给出读/写 token？未命中时长什么样？ |
| D7 | 失效 | 哪些改动导致 miss（中间插入、工具顺序、模型、路由参数、图片、时间戳）？ |
| D8 | 覆盖与隔离 | 哪些模型或接口支持？缓存按组织、项目还是密钥隔离？路由或区域限制？ |
