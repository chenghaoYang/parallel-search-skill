## conflicts
- 旧认知「必须手动打块级 cache_control」与现行文档不一致但非矛盾：2026-02-19 release notes 上线自动缓存（"No manual breakpoint management required"），块级显式断点仍保留且是多段缓存/精细控制的唯一方式；两种说法在各自时点都成立。
- 自动缓存可用范围随时间变化：release notes（2026-02-19）写 "Available on the Claude API and Microsoft Foundry (preview)"；现行文档写 "available on every platform except the legacy Amazon Bedrock (Opus 4.6 and earlier) integration" — 即新 Bedrock 后来才支持，两句以各自时间为准。

## gaps
- workspace 级隔离的变更日期未在 release notes 中定位到条目（web 摘要称 2026-02-05，但该日条目正文未见此句），仅确认现行行为。
- release notes 页面 via web_fetch 被 SSRF 拦截，改用 curl 取 HTML 人工比对日期标题；自动缓存条目位于 `<h3 id="february-19-2026">` 之下。
- 未独立核对 platform.claude.com pricing 总页，倍率取自 prompt-caching 页内定价表脚注。

## leads
- Bedrock/Vertex 非本家行为：旧版 Bedrock 不支持顶层 cache_control（400），Bedrock/GCP 用组织级隔离，Bedrock 最小 token 数见 AWS 文档。
- 观测增强：cache diagnostics beta（header `cache-diagnosis-2026-04-07`，`diagnostics.previous_message_id` → `cache_miss_reason`），2026-05-13 上线。
- 预热：`max_tokens: 0` 可预写缓存；mid-conversation system messages / `inline-tools-2026-09-15` beta 可在对话中插指令或改工具而不失效缓存。
