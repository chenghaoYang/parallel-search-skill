## conflicts
- 无直接冲突。注意表述差异：PEP 751 支持 multi-use 锁（extras/dependency-groups/environments），而 pip 当前实现（C4）只保证当前 Python+平台有效——是「实现子集」而非矛盾。

## gaps
- D3 workspace/monorepo：pip 文档无任何 workspace 概念（查过 cli 命令全列表、topics/workflow、pip install、pip lock、caching）；PEP 751 提到 monorepo 时锁文件放共同根目录，但那是格式规范而非 pip 功能。
- D9 迁移：无专门「requirements.txt → pylock.toml」迁移文档或 deprecation 时间表；pylock 支持仍标 experimental，requirements.txt 未被宣布废弃（查过 news 26.x 全部条目、topics/ 索引）。
- `pip lock` 对 PEP 751 multi-use 特性（extras、dependency-groups、environments 字段）的支持程度：pip lock 文档页未列限制清单，只有 C4 的平台限定声明。
- pip 文档未直接说「pip 不安装 CPython 解释器」字样；仅有 C13 的 scope 声明（managing interpreter not in scope），语义等价但非原句级否定。

## leads
- canonical pylock.toml 规范页（字段级细节留给后续轮次）：https://packaging.python.org/en/latest/specifications/pylock-toml/
- PEP 751 monorepo 锁文件放置约定（与 workspace 格相关）："If the lock file covered multiple projects in a monorepo, then the expectation is the `pylock.toml` file would be in the directory that held all the projects being locked."（peps.python.org/pep-0751/）
- pip 26.2 起 index 响应按 Cache-Control 缓存，新发包需 `--refresh-package` 刷新——影响 CI 里「刚发布就装」的场景（news #13680）。
