# deep-search

把问题查明白，再用读者容易理解的方式讲清楚。并行、词表、比较表和研究笔记都是帮你做到这一点的工具，不是每次都要完成的仪式。即使已调用本技能，简单问题也可以直接回答，不必扩成研究项目。

## 先弄清这次要回答什么

从用户的问题出发，抓住他们想理解什么、决定什么，以及哪些限制会改变答案。已有上下文够用就开始；只有缺失信息会实质改变研究方向时才追问。可以先说明合理假设，不用让用户填写一份研究问卷。

陌生领域里，先查几个关键术语、别名和容易混淆的概念，往往比直接大范围搜索有效。词表可以边查边改；已有知识只作线索，不把自己的叫法当成官方定义。需要这一步时再读 [references/vocab.md](references/vocab.md)。

## 让研究跟着证据走

先找能建立判断的资料，再决定哪里值得深入。不同问题可能适合按研究路线、实体、时间、争议或使用场景拆开，没有固定的分类轴。

能独立推进的问题可以并行，每个研究者应知道要回答什么、已有背景、边界和交付方式，避免几个人重复搜索整道题。主 agent 负责整合，也可以自己查资料、核对关键来源或处理跨方向的疑问。结果回来一部分就可以吸收和调整，不必为了等齐一批而停下所有有用工作。派工细节见 [references/worker.md](references/worker.md)。

每次得到新证据，问自己：现在还缺什么，会不会改变答案？有决定性的缺口就定向补查；遇到来源冲突就比较版本、对象、测试条件和原文。没有独立子问题时直接研究，不为并行而并行。没有子 agent 工具时按同样的证据标准顺序完成。

重要结论已有足够支撑，余下缺口不会改变主要回答时，就可以交付。用户要求持续追踪、穷尽指定范围或满足其他完成条件时，以该条件为准。达到用户给的资源上限仍有关键缺口，要交代限制；受阻或证据不足时给出能确认的部分，不用凑轮数，也不要把未查完说成已经查清。

## 对证据认真，对格式放松

- 优先读与主张最接近的一手材料：原论文、规范、官方文档、数据或原始记录。二手分析可以帮助理解和发现线索，但不要把搜索引擎的综合答案当成已经核实的原始证据。
- 关键事实要能找到支撑它的具体来源，链接靠近相关说法。需要比较数字时保留版本、样本、基线和测量条件；不同设置的结果不能直接排成高低榜。
- 分清来源明确说了什么、你据此推断什么、你建议怎么做。引用真实、可定位的内容；短摘录或页码、章节、表格位置通常比复制整页更有用。
- 对影响结论的“没有”“只有”“必须”“所有”“从某版起”等说法多查一步，找可能推翻它的例外、新版本或相邻文档。补查范围与用户所问的对象和版本相称。检索没找到、页面打不开、摘要没提到，都不能证明不存在。
- 交付前回到原始材料检查会左右判断的事实，尤其是数字、强否定、来源冲突和经过多次转述的结论。自己查或请独立研究者查都可以；只拿成稿对笔记，发现不了笔记本身的错误。
- 核验不了就缩小表述范围、标清不确定性，或删掉无支撑的细节。不要为了语气果断而编出处、掩盖分歧，或把“未核实”改成相反的断言。

## 写给真正会读的人

先回答用户最关心的问题，再解释理由和取舍。用自然的句子把概念之间的关系讲出来；术语第一次出现时简短解释，不要求读者先读一长页词表。避免空泛开场、反复总结、为了显得完整而堆出许多小节。

结构由问题决定：需要比较时用表，解释机制时用连贯的段落，步骤确实有先后时才编号。标题说内容，不把“taxonomy”“证据矩阵”“第几轮收束”等工作标签直接当成读者需要的结构。用户明确要求某种格式时照做。

把关键限制放在受它影响的结论旁边。确实有不少待解问题时再单列一节，不用每次附一套固定章节。单篇回答通常够用；只有用户需要反复查细节或篇幅确实妨碍阅读时，才另做附录、对照册或细节页。不要在几份文件里重复同一段内容。

修订时保留已有的好解释，替换不准确或低价值的部分；不需要每次从头重写。交付和复核的可选做法见 [references/converge.md](references/converge.md)。

## 参数与工作文件

仍接受旧用法：`/deep-search <任务> [--rounds N] [--workers N] [--budget CHARS] [--worker-model MODEL] [--dir PATH]`。

- `rounds`：组织研究批次时的上限，包括补查和核验批次；不是至少要做的轮数。
- `workers`：每批新派出的研究者上限，同时受工具的实际并发限制约束；不是人数目标。
- `budget`：主回答或 `report.md` 的字符上限，按 Python `len()` 计算并包含引用；不是 token 数或费用预算。没有指定时按用户需要控制篇幅，不默认写满 20,000 字符。附录也不能用来规避用户对总篇幅的要求。
- `worker-model`：只在环境支持且用户允许选择时使用；否则沿用环境模型，并说明无法满足的显式要求。
- `dir`：需要持久文件时的目录。未指定且确有文件需求时可用 `./deep-search/<slug>/`；简单回答不必建目录。

长任务可以留下简要范围、来源笔记和待解决问题，便于续接。只有对当前任务有用才创建 `brief.md`、`vocab.md`、`grid.md`、`log.md`、`notes/` 或快照。用户或评测明确指定 `report.md`、`./ds/`、快照等路径时仍按要求保存；交付前确认文件存在且是最终版本。

[scripts/notes_lint.py](scripts/notes_lint.py) 只用于旧版结构化笔记；[scripts/roundstat.py](scripts/roundstat.py) 可看篇幅和已有网格统计。它们都不能判断研究是否正确，也不要求为了通过检查改成固定文风。环境适配需要时读 [references/harness.md](references/harness.md)；历史变更见 [CHANGELOG.md](CHANGELOG.md)。
