# deep-search：扩展 → 收束 → 观察 → 下一步

你是主 agent（lead）。你只做四件事：定框架、派工人、收束成文、决定下一步。打开网页不在这四件里。一批派出之后、收束开始之前，只按「扩展」里的等待去做。
工人（worker）各拿一个窄问题去读一手来源，把压缩后的证据写成笔记文件。原始网页留在工人上下文里。

只扩展不收束 = 没做完。文档不许越改越长。每轮都要重写，不是追加。

## 参数（任务里没给就用默认）

| 参数 | 默认 | 含义 |
|---|---|---|
| `rounds` | 4 | 扩展轮数上限（R1…Rn）。至少 2 轮：R1 铺开，R2 起只打缺口 |
| `workers` | 10 | 单轮 spawn 上限。R2 起通常更少 |
| `budget` | 20000 | 成稿字符上限（`len()`，含来源节）。任何一轮快照都不得超过 |
| `worker-model` | 由 harness 决定 | 工人模型。见 `references/harness.md` |
| `dir` | `./deep-search/<slug>/` | 工作目录 |

## 工作目录

```
<dir>/
  brief.md                 R0：任务复述、范围内外、读者、完成标准
  grid.md                  taxonomy 网格：实体 × 维度，每格一个状态
  log.md                   每轮一段：观察 → 决策 → spawn 数 → 结果 → 字数
  notes/r<轮>-<slug>.md     工人笔记（格式见 references/worker.md）
  report.md                当前成稿（永远是最近一次收束的结果）
  snapshots/report.r<轮>.md 每次收束后的快照
```

网格状态：`✅` 有一手来源 + 原文摘录；`⚠` 只有二手来源；`⚔` 来源冲突；`❓` 缺口；`∅` 官方未写（已定向查过）；`—` 不适用。

## R0 定框架（不 spawn）

1. 写 `brief.md`：读者是谁、成稿要让他在几分钟内建立什么认知、范围内/外、种子词、用户点名的疑点（这些疑点必须在成稿里有明确结论）。
2. 起草 taxonomy v0，写进 `grid.md`：
   - 行 = 实体（种子里的对象 + 你预期的下游/兼容/变体对象）。
   - 列 = 比较维度（5–12 个，彼此正交；每个维度写一句「这一列回答什么问题」）。
   - 另列一组「分类轴」：把实体分成几个家族的依据（例如按协议谱系、按兼容目标）。taxonomy 是文档的骨架，不是附录。
3. 规划 R1：按**来源边界**拆题（一个实体或一个官方文档站一个工人），每个工人拿到自己那一行要填的全部维度。另派 1–2 个 scout 工人专找「这个范围里用户会踩的坑 / 你没列进网格的实体或维度」。scout 的产出只进 `leads`，不直接进成稿。

## 扩展（每轮一批 spawn）

- 一批里的简报彼此独立，同一条消息里一起发出（并行）。一次 spawn = 一个 turn；给已完成工人 SendMessage 追问也算一个 turn。在 `log.md` 里计数。
- 简报用 `references/worker.md` 的模板，必须写明：窄问题、要填的格子、不做什么、来源政策、笔记路径、返回格式。
- R2 起的每份简报必须点名它要解决的格子或主张（`grid.md` 里的坐标或笔记里的 `[C#]`）。R1 之后不许再派「再全面查一遍」式的简报。
- 整批发出之后、这一批返回之前，只许：把刚想到的缺口写成 `log.md` 的一行 `待查：<格子或主张>`，然后按 `references/harness.md` 等整批（一次调用，带上这一批全部 id），或结束本回合等完成通知。这之间不搜索、不开页面、不用 shell 取 URL，也不再 spawn。`待查` 留给下一轮简报，不在这个窗口里查。
- 返回之后主 agent 仍然不开页面。想自己打开某一页，就把它写成下一轮的一份窄简报，派一个工人。收束只读笔记，不中途开页面，也不中途插 spawn。
- 工人失败：最多重派一次（新 spawn，计数；重派后再按上面的方式等一次），仍失败就把它的格子记成 `❓` 并写明原因，不许静默丢掉。

## 收束（每轮之后，单独一步）

收束时不搜索、不 spawn，只用笔记。按 `references/converge.md` 做：

1. `python3 <skill>/scripts/notes_lint.py <dir>/notes` 看每份笔记的主张数、缺来源、只有二手来源、冲突、缺口、线索。
2. 更新 `grid.md` 每格状态。
3. 检查 taxonomy：有没有装不进任何维度的主张（→ 加维度）、全空或无意义的维度（→ 删或并）、分类轴是否真能解释差异（不能 → 换分类轴）。改了就在 `log.md` 写明 v0→v1 改了什么、为什么。
4. **从头重写** `report.md`，骨架见 `references/converge.md`，字符数不得超过 `budget`。新信息要挤进来，就删掉价值更低的内容，或把散文压成表格。写 `snapshots/report.r<轮>.md`。
5. `python3 <skill>/scripts/roundstat.py <dir>` 记录字数轨迹和网格填充率，贴进 `log.md`。

## 观察 → 下一步（每次收束后必做）

按下表挑**收益最高**的动作，写进 `log.md`（格式：`R<n> 观察：… → 动作：… → 预计 spawn：k`）：

| 观察 | 动作 |
|---|---|
| 关键格子 `⚔` 冲突 | 核验简报：把冲突双方的原句和 URL 交给新工人，只许看一手来源，判谁对、是否版本差异 |
| 核心格子 `❓` | 定向简报：一格或一簇格子一个工人，写明上轮查过哪些页 |
| 关键主张只有 `⚠` | 一手来源核验简报 |
| 要进「一屏看懂」或疑点结论的**边界主张**（见表下）还没反证过 | 反证简报（见表下），过反证前不写进「一屏看懂」 |
| scout/工人 `leads` 里有范围内的新实体或新维度 | 扩网格，派探索简报 |
| 分类轴解释不了差异 | 先在收束里换 taxonomy（不 spawn），再派需要的简报 |
| 字数超预算 | 只做压缩重写（不 spawn） |
| 核心格子都是 ✅/∅ 或上一轮几乎没改变网格，且进「一屏看懂」和疑点结论的边界主张都已反证；或轮数用完 | 终审（下一节），然后停 |

**边界主张**：否定（不支持、没有、未提及、`∅`）、排他（唯一、只有）、强制（必须、仍需）、全称（所有版本、一律）、时间边界（自某版起、仍是预览、已弃用），以及与常识或旧版本相反的说法。一句原文只能证明这一页写了什么，证明不了别处没有、后来没变，所以这类主张最容易错。先拿自己的 grid 和笔记找反例（不 spawn）；找不到，就派反证简报：把主张、原句、URL 交给新工人，只许它找反例（更新的 changelog / release notes、API reference、同一来源的其他页），同一来源站点的几条打包给一个工人。有一手反例就改写；没有才保留，并写出范围（「截至 <日期>，<查过的页> 未见」）。核心矩阵里的否定格按影响挑着反证。

每一轮的简报应当比上一轮更少、更窄。一轮只派必要的工人，不要为了「大规模」凑数。

## 终审与停止

终审不派「对笔记抽查」的审稿工人——笔记本身可能就是错的源头。终审核验**回原页**，三步：

1. 列核验清单（不 spawn）。从当前 `report.md` 挑「错了就误导读者」的主张：
   - 「一屏看懂」每条、用户点名疑点的每条结论——全部进清单；
   - 坑里每条的具体事实（数字、版本、字段名、行为规则）；
   - 矩阵格：被一屏/疑点/坑引用的、`⚔` 裁决后写进正文的那一边、单源支撑的高影响值。
   - 排除：本轮已走过反证简报的主张（`log.md` 有记录）。
   一条主张涉及多个来源就拆成多条判定项（一个 URL 一条）。按 URL 域名/实体聚簇，一簇一个核验工人；每工人 ≤ 10 条，核验工人总数 ≤ `workers` 上限。装不下按 一屏 > 疑点 > `⚔` 裁决 > 坑 > 其他矩阵格 截断，截掉的在 §5 声明「未逐条核验」。
2. 派核验工人（同一批，模板见 `references/worker.md`）：简报逐条给 成稿原句 + 笔记摘录 + URL；工人回原页核对，逐条判 `confirmed / wrong / not-on-page / 走样`（判定口径见 worker.md）。判定表汇总写进 `audit.md`。
3. 按判定改稿（不再 spawn）：`wrong` 且附了页面原句 → 按原句改正，`[n]` 保留；`wrong` 无原句、`not-on-page`（页面打开了但没写）→ 删或移进 §5 标「未核实」；`not-on-page`（页面打不开）→ 不删，标「未核实」；`走样` → 改回摘录的说法。一屏/坑与矩阵对不上的概括句，改成与矩阵和笔记原句一致，并带上该格的 `[n]`（`[§k]` 不算来源）。「没找到来源」不等于「不支持」：不许把无支撑主张改写成相反否定句。改句不许把来源节的 URL 缩写或删掉。改完跑 `roundstat.py`，若有 `cite:`，按笔记 `src` 补回完整 `https://` 和缺的 `[n]` 再交。没进清单的具体事实不另派工人，按硬规则自查：每条追到笔记 `[C#]`，追不到的删/降级。
4. 最后一步必须是收束，不能停在扩展。成稿末尾保留「未决与置信度」一节，写清还空着的格子。

## 硬规则

- 主 agent 不调用网页搜索或抓取，也不用 shell 取 URL。缺的信息派工人。工人自己的搜索，以及终审核验工人回原页核对，不受这条限制。
- 一手来源优先（官方文档、API reference、changelog）。搜索引擎的综合答案（如 Perplexity）只能当线索，不能当来源。
- 成稿里每个具体事实都能追到一条笔记主张；没来源的写进「未决」，不写进正文。
- 不并行写成稿；成稿只由主 agent 写。
- 用户点名的疑点，成稿必须给出结论（哪怕结论是「官方没写」）。
- 不许为了凑轮数或凑人数派工人；也不许在只有一轮扩展时就交稿。
