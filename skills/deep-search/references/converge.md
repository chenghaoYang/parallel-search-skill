# 收束：成稿骨架、分层交付、taxonomy、长度控制、审稿

收束只用 `notes/` 和 `vocab.md`，不搜索、不 spawn。每次收束都**从头重写** `report.md`（开了 `atlas.md` / `details/` 的一样），不是在上一版末尾追加。

## 分层交付（report / atlas / details）

目标是同时拿到「快速建立认知」和「字段级细节」，但不许重演手册式臃肿（135k 字、跨页重复）：

| 层 | 文件 | 预算 | 放什么 | 什么时候开 |
|---|---|---|---|---|
| 导读 | `report.md` | ≤ `budget` | 全部结论：一屏看懂、词表、taxonomy、核心矩阵、坑、未决 | 必须有，单独成立 |
| 字段对照册 | `atlas.md` | ≤ 2 × `budget` | 全部维度 × 全部实体的字段级表格，每格 [n]，不复述结论 | 核心维度以外的字段细节被 budget 压掉时 |
| 细节页 | `details/<slug>.md` | 每页 ≤ 4000，≤ 8 页 | 一个窄主题的整页叙事：坑的展开、迁移指南、检查清单 | 值得整页、又不该占导读预算时 |

- **去重规则**：字段级事实只在 atlas 写全，叙事/操作只在 details 写全；report 只放概括 + 指针（`字段级对照见 atlas §k`、`迁移步骤见 details/migration.md`）。指针句不引入新事实就不用 [n]。内容（表格、散文、清单）不许在两层之间抄两遍；同一 URL 允许在多个文件的来源节出现，但每处只列该文件实际引用的条目。
- **引用各自解析**：report 的 `[n]` 指 report 来源节；atlas / details 的 `[n]` 各指自己页尾的来源节。
- 两层都是可选的：简单任务只有 report 就够。开了之后每轮收束同样从头重写；快照只拍 report，atlas / details 的字数记进 `log.md`。

## 成稿骨架（report.md）

读者要在 5 分钟内建立认知，再按需往下查细节。层次固定，不要改顺序：

```
# <标题>
> 这份文档回答什么；截至日期；怎么读（2–3 行，指向 atlas / details）

## 0. 一屏看懂
5–8 条结论。每条一句话，说出最重要的差异和它的后果。用户点名的疑点在这里先给结论。

## 1. 先认识这些词
从 vocab.md 压缩：入口词、骨架词每词一行一句；暗号注明易混邻域；外行→标准名一张小表。
没核验的词照登（保留 ⚠ 口径），不编官方出处。格式见 references/vocab.md。

## 2. Taxonomy
分类轴 + 家族划分（一张表或一棵树），每个家族一句「为什么它们是一类」。
再给维度清单：每个维度一句「这一列回答什么问题」。后面所有表都按这里的维度排。

## 3. 对照矩阵
核心维度（建立认知必须的那几个）一张表：行 = 实体，列 = 该维度下的具体字段/取值。
写原名（字段名、路径、枚举值），不要意译。格子里放 [n] 引用。空格写 ❓，官方未写写 ∅。
全部维度的字段级对照放 atlas.md（若开）；本节只留核心，不和 atlas 抄重。

## 4. 变体与适配层
「兼容 X」的实体相对参照协议差在哪：一张差异表（实体 × 差异点），再加少量必须解释的散文。

## 5. 用户需要知道的坑
每条：现象 → 原因 → 怎么处理 [n]。按踩中的概率排序。
选型/接入类任务，末尾收一张「上手检查清单」（动手前逐项过一遍，每项能追到 [n]）。

## 6. 未决与置信度
还空着/冲突/只有二手来源的格子；官方文档之间的矛盾；时效风险（页面日期、预览功能）。

## 来源
[n] 标题 — URL（官方在前；去重；只列正文实际引用过的）
```

## atlas.md 骨架

```
# <标题> · 字段对照册
> 只放字段级对照，不复述 report 的结论。怎么读（1–2 行）。

## <维度一>
行 = 实体，列 = 字段/取值/默认值。写原名。空格 ❓，官方未写 ∅，每格 [n]。

## <维度二>
…

## 来源
[n] 标题 — URL
```

## details/<slug>.md 骨架

```
# <主题>
> 这页回答什么；什么时候需要读它（1–2 行）。

正文：一个窄主题讲透。具体字段回指 atlas 的格（带其 [n]）或自带 [n]。

## 来源
[n] 标题 — URL
```

## Taxonomy 写法

- 先分家族，再比细节。家族按「分类轴」划（例如：请求形状继承自谁、状态放在哪一端）。分类轴要能解释矩阵里大部分差异；解释不了就换轴，并在 `log.md` 记下换轴理由。
- 维度彼此正交，名字是问题而不是名词堆（「对话历史谁来保存？」好过「状态」）。
- 同一事实只在一个地方写全。别处可以标「见 §k」，但句中的具体事实仍带原处的 `[n]`；`[§k]` 不是来源。

## 长度控制（不许越改越长）

- 任何快照 `len(report.md) ≤ budget`（含来源节）；`atlas.md` ≤ 2 × budget；每个 details 页 ≤ 4000。超了就压缩，不能交。
- 第 2 轮起，每次重写要在 `log.md` 写：新增了什么、为了它删了/压了什么、字数前后变化。
- 分级：P0 = 用户点名的疑点、taxonomy、核心矩阵，不删；P1 = 坑、适配差异，压成表；P2 = 背景、历史、次要实体，先删。
- 压缩手段按顺序：删重复 → 散文改表格 → 合并相邻行 → 次要实体并成「其他」一行 → 删 P2 → 字段级细节下沉 atlas（若已开）/ 开 atlas。
- 不要用「详见来源」糊弄正文；矩阵里该有的字段名必须在。

## 引用

- 正文每个具体事实后面带 `[n]`，`[n]` 指向来源节。来源节里的 URL 必须来自笔记的 `src`。「一屏看懂」同样如此，不能只标 `[§k]`。
- 来源节里的地址照抄笔记 `src` 的完整 `https://` URL。不要去掉协议，不要用花括号或省略号把几条合成一条。重写时可以删掉正文已不再引用的条目，不能把还在引用的 URL 写成缩写。
- 只有二手来源支撑的事实加「（二手）」，或放进第 6 节。
- 笔记里互相冲突的，正文写能确认的那一边，另一边和原因写进第 6 节。

## 核验（终审工人用）

核验清单怎么挑、核验简报怎么写，见 SKILL.md「终审与停止」和 `references/worker.md`。
核心差别：核验工人**回原页**核对，不是拿成稿对笔记——笔记本身可能就是错的源头。

主 agent 收到判定表后：

- `wrong` 且附了页面原句 → 按原句改正，`[n]` 保留。
- `wrong` 没附原句、`not-on-page`（页面打开了但没写）→ 删除或移到第 6 节标「未核实」。
- `not-on-page`（页面打不开）→ 不删，标「未核实」；可能是网络或站点问题，不等于主张错。
- `走样`（成稿≠摘录）→ 改回摘录的说法。
- `confirmed` → 不动。
- 一屏/坑与矩阵对不上的概括句 → 改成与矩阵和笔记原句一致，并带上该格的 `[n]`。
- 词表走样（官方不这么叫）→ `vocab.md` 和「先认识这些词」两处一起改。

没进核验清单的主张不另派工人，靠「每条具体事实追到笔记 `[C#]`」自查；被截断没核上的在 §6 写明。
把判定汇总写进 `<dir>/audit.md`，改完再跑一次 `roundstat.py`；若有 `cite:`，按笔记 `src` 补回完整 `https://` 和缺的 `[n]`。终稿同样受 `budget` 约束。
